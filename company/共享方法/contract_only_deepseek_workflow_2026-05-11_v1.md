# 公司级流程候选：合同优先与 DeepSeek 正文外包 v1

- 状态：approved/shared-methods
- 日期：2026-05-11
- 类型：公司级流程候选
- 注意：本文未进入 company 正式标准；需作者审批后，主 agent 才能同步更新公司级正式方法文件。

## 一、流程目标

后续小说生产改为“主 agent 只生成详细合同，外部正文模型负责写正文”的模式。主 agent 不再默认直接写章节正文，而是把章节写作所需的上下文、结构、人物、世界规则、情绪曲线、场景推进、禁区和验收标准整理成可独立投喂 DeepSeek 的合同。

## 二、核心原则

- 合同必须可独立使用：外部模型不知道前后文，也应能根据合同写出符合本书的章节。
- 合同比普通大纲更细：不只写剧情点，还要写人物状态、情绪变化、信息揭示边界、世界组织背景、场景结构、文风禁区和验收清单。
- 正文不进入主 agent 默认产物：除非作者明确要求，否则主 agent 不生成 `chxx_draft`。
- 正文由外部模型生成后，应回流到 candidate，再由 review 部审阅，最后走 patch 和 approval。
- 正式区仍只接受审批后的内容。

## 三、DeepSeek 章节合同推荐结构

每章合同至少包含以下部分：

1. 给外部模型的工作边界：只写正文，不输出分析；视角、字数、文风要求。
2. 全书最小背景：只写本章需要知道的世界、主角、势力和主线方向。
3. 前文已发生：上一章或此前剧情的关键状态。
4. 本章位置：本章在卷、阶段、黄金三章或中段剧情里的功能。
5. 核心冲突：本章最主要的外部冲突、内部冲突、隐藏冲突。
6. 出场人物：每个人的身份、当前状态、说话风格、本章功能、与主角关系。
7. 世界/国度/组织背景：本章会涉及的国家、教会、贵族、地理、制度、超凡规则。
8. 信息揭示边界：必须揭示什么，禁止提前揭示什么。
9. 情绪曲线：情绪起点、升级点、反转点、落点。
10. 场景结构：每个场景的进入方式、冲突、关键细节、结果和转场。
11. 必须写出的具体抓手：物品、动作、声音、气味、伤口、食物、地形等。
12. 人物声音与台词方向：避免所有角色同腔。
13. 本章写法策略：从悬念前置、期待吊钩、证据阶梯、信息差、行动计划、规则链、建设爽点、对话试探、结尾反钩中选择适合本章的模块，并写清执行方式。
14. 场景级钩子：每个主要场景如何把读者拖进下一场，避免一场一场平铺过去。
15. 文风要求：语言密度、段落长度、口语化程度、禁用 AI 口癖。
16. 禁区：设定禁区、剧情禁区、人物 OOC 禁区。
17. 结尾钩子与验收清单：读者读完必须知道什么、期待什么。

## 四、产物流转

1. 主 agent 读取公司标准与书内正式真相。
2. 主 agent 生成 `candidate/contracts/contract_chxx_vN.md`。
3. 作者确认合同方向，或合同经审批入 `approved/current/contracts/`。
4. 作者把合同交给 DeepSeek 写正文。
5. DeepSeek 正文回到 `candidate/drafts/`。
6. Review 部审阅正文，Bible 部检查状态差异。
7. 主 agent 生成正文 patch 与 approval。
8. 作者批准后，正文或设定差异进入 approved/current。

## 五、默认禁令

- 未经作者明确要求，主 agent 不直接生成正文 draft。
- 外部模型生成正文前，不能只给一句话大纲。
- 合同不能假设外部模型知道本书前情。
- 合同不能省略人物声音、情绪曲线和信息边界。
- 外部正文不得绕过 candidate 直接进入 approved。
