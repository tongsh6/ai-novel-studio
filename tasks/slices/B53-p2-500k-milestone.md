- 上游：`docs/product/novel-output-milestones.md` §5 P2、[P1-word-count-audit](P1-word-count-audit.md)、[B39](B39-evidence-seeking-authoring.md)。

## 1. 目标与边界

P2 是新的产品里程碑，不是把 P1 canonical 轮次改成 500K，也不是用脚本堆字：

- ≥500,000 有效字，且每章 ≥2,000；
- 有分卷结构；
- 每 10 章有剧情摘要或阶段状态；
- 人物状态、伏笔、canon 可追踪；
- 随机至少 25 章通过连续性检查；
- 能从最近章节继续写，重开不丢上下文；
- 导出目录、章节顺序和正文完整。

P1 的既有 100K 证据与后续 scoped 结果分别保留；canonical-3e 的 12,894 字不是 P1 100K 本身，更不是 P2。I10 文学盲评和工程达标分属不同结论。

## 2. 启动条件与开工七问

### 启动条件

- P1-word-count B/C 的缺章/重复审计已具备；
- `@audit_stage` 已从硬编码 P1 升级为作品级配置；
- 作者批准预算、模型、长跑窗口与原生监督；
- 按真实需求确认是否先具备 B39 的连续性求证与 I10 基线，不把 B39 当字数工具。

### 七问

1. **Contract**：P2 验收指标、作品级阈值、分卷/canon/摘要/恢复/导出、B37 预算监督与外部真实页面证据。
2. **Invariant**：有效字和章字数由确定性计算，计划章不冒充正文；未采纳不计入 canon；跨重启不重复；禁止脚本堆字数、重复段/章凑数和 LLM 自报完成。
3. **Boundary**：复用现有创作/采纳/阅读/审读/导出主链、P1 审计、任务监督与模型生命周期；不为里程碑新建另一套生产框架。
4. **Consumer**：作者的中长篇连续创作、ReadingMode、连续性审读和里程碑审核者。
5. **Proof**：≥500K、每章≥2000、分卷、25 章随机连续性、重开续写和完整导出；真实工作台驱动，保留失败/重试与模型生命周期证据。
6. **Acceptance Driver**：外部自动化真实页面完成连续创作、维护、恢复、审读与导出；产品验收感知逻辑 **no**，长跑须作者另行拍板。
7. **Exploration**：人物状态/伏笔/canon/摘要可按通用探索读取与复核，不新建固定 prompt packet；连续性证据与 word-count.json 可重算。

## 4. 非目标

- 不把 P1 canonical 轮次或旧 100K 证据改写为 P2，不把 P2 当 P1 的重复跑分。
- 不用脚本堆字、重复段/重复章、计划章或未采纳正文凑里程碑。
- 不把 `@audit_stage :p1` 的阈值直接当 P2 配置，不抢 B39 或 P1 B/C 队首。
- 不提前吞并 P3/P4、LongRunner 批量生产或 Multi-Agent。

## 5. 验证与恢复

- P2 各项指标由真实工作台与可重算证据达成，原生/浏览器/实模与文学评价分别记录。
- 重开后能继续写最近章节，不丢上下文、不重复正文，导出完整。
- 恢复时先读 P1 B/C、B37 预算与 B39 状态；若预算/负责人未批准，保持 deferred。
