# B68：经验提炼、审阅与规则生命周期（条件触发）

- 状态：**deferred（2026-10-30 登记完整承接；保持既定延期，尚未启动设计冻结、实现或模型运行）**。
- 来源：作者要求把 schema 后续与 Experience Engine 的延期责任纳入任务队列；[逐文件对账 §14](../2026-10-27-design-to-execution-reconciliation.md#14-2026-10-30-逐文件设计承接核对) 发现原 [Experience Engine 设计](../../docs/design/domain/33-experience-engine.md) 只有局部 dismiss 收编记录，缺完整任务。
- 本文件成为经验证据→提炼建议→作者审阅→规则生命周期→后续消费/解释的唯一任务入口。登记补上责任归属，不表示该设计的全部字段已冻结、功能已实现或当前应该启用引擎。

## 1. 作者场景与目标

作者在同一作品中反复采纳某类改写、否决某类写法，或希望把有出处的复盘结论变成后续可用规则。系统应能提出可审阅的经验建议，说明来源与适用范围；作者可以接受、拒绝、禁用、替换或归档，并能在后续创作中查明使用了什么。

该场景不同于直接保存作者的一条明确创作方向，也不同于故事事实、角色主档案或五账进度。经验推断不得绕过现有采纳/批准边界，不得把一次临时选择升格为永久偏好，不能静默修改 canon、写作偏好、质量门或执行权限。

## 2. 重新开放条件

保持 deferred，直到以下条件明确：

1. 作者提出真实经验复用需求，并能给出首个作品场景、可使用的证据范围和期望消费者；不能仅因设计文档存在就启动。
2. 先比较现有记忆治理、方向持久化、风格对象与反馈机制能否满足需求；若可满足，回原 owner 收敛，不搭重复引擎。
3. 明确首批经验来源、审阅权限、作用范围、撤销/失效与保留策略，并给出可审阅的最小 contract/必要 ADR 和场景方案。涉及模型运行时按具体预算与资源安排执行。

触发后先把 CP0 转为 todo 并核实当时真实实现。新增字段、规则自动生效方式、模型窗口和作者现有数据操作不由本次登记自动放行。

## 4. 开工七问（启动时按真实场景细化）

1. **Contract**：domain/33 的证据/建议/规则与审阅边界、现行记忆/上下文契约、采纳与批准策略、ADR-0030/0031。原设计中的旧 ADR 编号和旧卡片建议须先与现行决策面校准，不能按旧示例直接冻结新字段或卡型。
2. **Invariant**：经验有真实来源且不冒充作品事实；一次信号不自动成为永久规则；适用范围和权限明确；高影响变更经作者审阅；失效/禁用可执行、历史可追溯，失败/重复请求无重复权威副作用。
3. **Boundary**：domain 仅纯规则，application 负责证据组装/提炼与审阅编排，agent 复用现有 ProviderExecution，persistence 复用或按真实需要保存引用/版本，web/frontend 提供真实审阅和解释消费者。不增加常驻多 Agent 或独立知识库。
4. **Consumer**：首个由触发场景指定的作者审阅入口及后续真实创作/复核请求；没有消费者的规则类型不先实现。质量或预算政策建议沿各自批准 owner 生效。
5. **Proof**：证据到建议、审阅到激活、作用域/版本/禁用与历史回放的局部正反例；实际模型请求与可见 Why 对账；规则被提供、模型遵循及文学收益分别证明，I10 仍由人工判断。
6. **Acceptance Driver**：外部驱动真实 Tauri 产生受控来源→查看经验建议→接受/拒绝→新会话消费→禁用/替换→再次验证；覆盖跨作品、来源失效、重复和恢复。具体 driver 在 CP0 冻结；产品验收感知逻辑 **no**。
7. **Exploration**：经验来源和已接受规则通过既有通用查询/探索面同批可达；观察与后续请求保留来源、版本、适用范围，used refs 不越界；无消费者的经验不预装固定 packet。

## 6. 非目标与恢复

- 不实现模型微调、自动商业成功判断，不把作者一次编辑或否决解释成永久喜好。
- 不静默改写 policy、budget、tool 权限或明确设定；不因收集证据就启用每日后台归纳。
- 不替 B50 重新开启独立多 Agent/24x7，不把 B55、B56 或 I10 的延期范围自动纳入当前实施。
- 接手时先核本任务触发条件与最新原任务/契约，再选择 CP；仍缺真实消费者时保持 deferred。本次只完成登记，没有产品、数据或模型变更。
