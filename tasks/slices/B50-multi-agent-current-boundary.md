## 2. 待评方案

- **保留**：必须给出真实消费者、父子运行时边界、预算与故障恢复，不以模块名凑实现。
- **延期**：保留未来委派可能，但明确当前不承诺 24x7/独立进程，并把触发条件写清。
- **Supersede**：以统一 AgentRun 为当前权威，记录旧决策替代关系，不重写历史或删除证据。

**2026-10-28 评审推荐：延期（待作者确认）**。当前先交付统一 AgentRun 的真实消费者，暂不承诺 day-1 独立进程与 24x7 Reviewer/Maintainer；保留未来委派方向。重新开放的条件是有明确独立任务、输入/输出、父子预算、权限、取消、crash/handoff 恢复与真实页面证明需求。此建议不由“模块缺席”直接推导退役，不授权新 runtime，也不自动修改 tech08 的历史决策；作者选定后由 B51 更新当前适用口径与历史关系。

### 2026-10-30 C05 讨论边界

本项决定首期是否必须交付“独立角色 Agent、父子委派与全天候 Reviewer/Maintainer”的完整产品承诺。专业模型调用、不同任务 profile 或多个 run，本身不等于该承诺已实现；统一 AgentRun 也不必然排斥未来父子任务协作。

- **A 保留首期必须**：将独立角色/并发收益、权限收缩、总预算、取消、崩溃/恢复与交接纳入当前产品验收，需要明确真实消费者；与已接受统一 AgentRun 衔接，不暗建第二控制循环。
- **B 延期（推荐）**：当前先完成统一 AgentRun 的创作/求证闭环，保留未来委派方向；出现真实独立任务、可说明的收益、父子权限/预算/故障边界与可执行验收时再开放，不给无依据日期承诺。
- **C 正式替代旧首期强制要求**：将当前架构权威明确为统一 AgentRun，按正式设计/ADR 关系保留旧记录；未来多 Agent 作为新决策评审，不能直接删除旧文档或卸载依赖。

B 与 C 都不表示永久禁止多个专业角色；区别是保留既定未来方向，还是正式替代旧强制路线。本项仅讨论小说产品架构与交付边界，不是授权当前开发助手启动子代理，也不触发安装/升级、后台常驻任务或真实模型运行。作者选择及延期边界见 §6。
