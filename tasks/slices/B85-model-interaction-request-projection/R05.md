# R05 — 当前事实、作者要求、真实 Observation 的来源边界：一次独立 AI 编码会话执行指令

## Goal（唯一交付目标）
系统不能把“作者想要的结果”标记为已发生事实，不能把应用基础投影伪装成已调用工具的 Observation。

## 上游前置条件（不满足不得开工）
R00、R04；检查 VS-00L / RequestIR 当前 provenance/refs 能否承载；若需主协议字段变更先获契约批准。

## 范围与不可变边界
**允许**：优先现有 RequestIR / JudgmentProtocol 的请求事实投影与来源校验，相关 tests；不建新持久事实表。

**禁止**：不引入第二模型交互事实源、不凭标题推造 artifact_type、不自动生成 observations、不把作者指令塞进 application scope 冒充系统事实。

## 执行计划（必须在本会话完成）
1. 对输入区分四类：base_facts、author_requirements（由真实作者消息引用）、model_inference、tool_observations。
2. 为每类定义允许的 source_ref、version、coverage/status 与事实引用规则；已存在结构优先复用。
3. 测试应用章索引不会出现伪 tool_call；真实 chapter_read 才产生 observation 且绑定真实 call_id；未读、stale、partial 诚实传递。
4. 保持三 Provider 原生消息投影与后续模型消费的一致性。

## DoD（必须全部满足）
- [ ] 无法以应用统计冒充“已读取整章”或“已执行 work_archive_read”。
- [ ] 作者期望与当前状态不会因请求组装混同。
- [ ] 已绑定的真实 refs、投影顺序及旧消息回放行为保持。

## 专属验证
judgment_initial_snapshot_test.exs + authoring_transcript_test.exs + authoring_execution_refs_test.exs + 相关三投影回归 + 共同门禁。

## 交付结果
来源类型与已验证绑定行为，不是另一份持久化 JSON 真源。
