# R10 — 授权体系：风险等级、授权模式与 critical/full 边界：一次独立 AI 编码会话执行指令

## Goal（唯一交付目标）

在现有 RequestIR / JudgmentProtocol / Orchestrator gate 上增加可机械校验的授权层：能力风险等级（按 `capability + effect + target` 动态）、用户授权模式（`manual / risk_based / full / smart`，run > 会话 > 作品 > 全局）、`critical` 询问作者、`full` 自动采纳的委托与审计；不修改 RequestIR 真源，不新建 ModelInteraction 持久化结构。

## 上游前置条件（不满足不得开工）

R05、R06 PASS；[VS-00M](../../../docs/design/contracts/VS-00M-model-interaction-request-response-contract-pack.md) §3.4/§3.6 作为设计输入；B81 当前机制不重做；若需改 Frozen 契约，先获 ADR/契约批准。

## 范围与不可变边界

**允许**：优先 application 的授权决策/风险规则模块、Orchestrator gate、JudgmentProtocol 的 `authorized` 派生与 validation 字段；domain 纯函数 `risk_of/4`；相关 tests。

**禁止**：不新建 ModelInteraction 持久化真源；不重写 RequestIR 三 wire 投影；不让模型自评风险或自授模式；`full` 自动采纳不得绕过 adoption boundary / I1 / validation；不改变现有七工具语义。

## 执行计划（必须在本会话完成）

1. 定义 `risk_of(capability, effect, target, context)` 纯函数与可版本化规则表：`low / medium / high / critical`；`critical` = 删除、批量（≥3 对象）、不可逆覆盖、跨作品、改 canon 核心。
2. 实现授权模式解析：run > 会话 > 作品 > 全局；记录 `mode_source`；模型不可设置或修改模式。
3. 实现 `authorized` 派生：从 `authority_scope.allowed_tools` + profile/step + 前置条件 + budget 派生，替换判断器硬编码 `@judgment_capabilities`；catalog 仍按需 `capability_lookup`，不预装。
4. 实现决策矩阵：`low/medium/high/critical` × `manual/risk_based/full/smart`；`critical` 恒 `ask_author`（同意=执行+采纳，拒绝回流，永不自动采纳）；`full` 自动采纳需 `delegation_ref`、可撤销、可回滚、`status_message` 明确标注。
5. validation / truthfulness 增加 `risk_decision` / `author_decision` / `auto_adopted` / `author_confirmed` / `author_delegation_ref`；系统回填，模型不能自填。

## DoD（必须全部满足）

- [ ] 授权矩阵与 VS-00M §3.4.3 一致；`critical` 恒询问作者；`full` 自动采纳有 `delegation_ref` 且可回滚。
- [ ] `authorized` 从 run 事实派生，与执行 gate 同源；模型建议 ⊆ `authorized`。
- [ ] 风险函数可重算；模型不能自评/自授；不破 I1 / N-NARR / I-CACHE。
- [ ] 现有判断/创作/修订链不退化；三 wire 投影不变。

## 专属验证

authorized/risk policy 单测 + 授权矩阵负例 + judgment_protocol_test + execution_authority_test + 共同门禁 + 一次真实 run 证据。

## 交付结果

授权体系实现、矩阵负例、真实 run 证据、`full` 自动采纳审计样例。
