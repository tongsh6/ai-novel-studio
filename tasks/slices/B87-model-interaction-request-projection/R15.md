# R15 · Full 真实自动采纳与事务回滚闭环

> **唯一目标**：只有作者有效委托范围内的非 critical 创作结果才能走已有 AdoptionWorkflow/Repository 合法自动采纳，并带可撤销审计
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)；本卡只承载当前会话执行契约，[README](README.md) 为全部批次共享门禁。

## 开工前置
R14 PASS；必须先核实 AdoptionBoundary、AdoptionWorkflow、ReceiptRepo、CanonFreshness 的原子事务与现有编辑采纳行为。

## 真实改动范围
现有采纳执行入口、对象版本/有效委托检查/作者可见状态；禁止 AutoAdoptionService 第二写库、跨作者权限。

## 一次会话内必须执行的完整步骤
1. 创建 tentative 候选仍由真实 Provider/作者原话字节产生，先完成 schema/effect/refs/风险/工作范围/版本/委托检查，再经过现有采纳边界。
2. 从 R14 持久委托及签发版本精确构造执行决定，同一个事务进行重复 idempotency 与 canon 更新/回执，失败不改变可见或已采纳事实。
3. 中途撤销、并发修改、重复回调、候选越界/过期、不可逆 critical、无法回滚的 effect 等都不得自动采纳。
4. 实际作者界面标注‘自动采纳/来源/对象/版本/撤销范围’，Replay 保留系统来源，不允许模型声明‘我已经保存’替代真实回执。

## 反例与不可逾越的禁止项
严禁通过 extra 参数绕过 AdoptionBoundary 或对 confirmation_satisfied 填 true 冒充委托；不得宣称所有 canon 改动可回滚但没实际回滚机制。

## Definition of Done（不可打折）
完整 Tauri + 原生候选→自动采纳→DB/阅读投影/Receipt 正例及拒绝/撤销/回滚负例；零越权，I1/N-NARR 维持。

## 作者真实使用场景与验收效果
作者确实可以选择自动工作，同时每次实质性的作品事实改变仍可核对、撤销并追踪。

## 交付与恢复纪律
- 先从当前 HEAD 验证依赖、七问、拟新实体查重/复用、old→new 消费者以及需要改的 Frozen 契约；不得根据任务卡推测已经实现。
- 当前批次必须把所述目标、异常与负例、真正消费入口、必要文档/测试/代码/迁移/旧入口删除收在**同一次可验证交付**，不能把必要验收债务交给下一批。
- 按共享 README 跑完整适用门禁与真实用户入口；模型行为须实模证据，确定性替身不可代签。只有真实 PASS 才形成提交并更新 B87 唯一状态源；不可重放/不可执行时如实 FAIL/BLOCKED，保留失败证据与恢复条件。
