6. **Acceptance Driver**：复用 `native_request_cost_batch.sh` / `native_request_cost_drive.mjs`，使用原冻结 manifest 的 3 轮和完整隔离作品快照，`REQUEST_COST_ARTIFACT_DIR` 指向全新 R02 证据目录；外部只读断言，不新增 runner/产品逻辑，不重跑 20 轮。
7. **Exploration**：不物化新要素；复用既有对象 ref/探索工具。Scope 明示 index-only/正文未读/遗漏，缺口由实际探索读取并回流 observation，used_refs 仍绑定 Base∪真实观察，不以缺少 packet 推定不存在。

### 实际身份与作者源裁决

- `DialogueContext.work_id` 是唯一作品身份；`WorkspaceContext.query`、`ContextAssembler` 与全部 flow 从 `run.work_id` 实读，不用 workspace 名称代替作品。工作台关联字段继续属于原 run/日志 owner。 当前 DPS/Prose 的消费点统一使用 run.work_id，启动 spec 缺作品身份交由既有 AgentRun required 校验拒绝，不回填 workspace_id 或优先使用旧闭包 input.work_id。单测必须包含 workspace_id 与 work_id 不同的真实数据库读取。
- 首轮作者输入来自真实输入命令的 `interaction_input.text`；后续 goal v2/steer/自由答复必须按 work/session/run/turn 查询既有 Interaction receipt。旧 planner closure、裁剪的会话预览、normalized goal 都不是原文字节 fallback；缺失或冲突 fail closed。
- `TurnInteractionService.author_input/2` 一次选择既有 `%{turn_id, text}`：首轮取显式命令，后续取同一条精确 receipt；文本与来源不能分别读库或按版本另造。DPS、五个 planner 调用、两个 mission 调用、直接专业 flow、候选/已采纳/整章修订与 Prose continuation 同批消费；确认子 run 使用已有 author_message.text/turn_ref。
- 专业 `author_input.text` 只承担原文；应用拼接的 goal/AgentStep/观察/guidance 移到既有创作简述职责 `creative_brief`。`AuthoringTaskBuilder` 只接显式 `author_words`，不再从 `author_goal_text` 或模型说明补作者话。`CreativeRequest.source_input_ref` 仅透传同一原文选择的来源，不建立第二作者模型。
- `AuthoringSession.record_author_input/3` 复用现有 Transcript 追加机制：已有任意位置的同来源同字节保持幂等，同来源异字节拒绝；新真实输入按原序追加。common Operation 仅在初始请求消费显式 text/ref，continued 的作者追加由 application 完成，不由 common 推测 steer 或读取数据库。 Operation 与 text_operation 收敛到已有 RequestIR 作者消息构造器；仅两个 nil 或完整非空白配对合法，首操作/standalone/continued 均拒绝半对，不再回退 parent_turn_ref。Quality 与辅助叙述共用已有 AuthoringTask 作者动作来源读取，不把候选材料回合或质量触发 ref 补为作者。 Judgment/Transcript 同批消费该纯契约；删除占位作者 ref 与合成 run_id，Judgment 必须提供实际 plan_run 或既有 transcript。纯应用 continuation 可明确无作者。
- 已证实的辅助叙述链 `TurnExecutionService → AuxTaskBuilder.for_result_narration → Planner → RequestIR.Operation.text_operation` 同批修正来源：唯一输入为真实 `author_input %{turn_id,text}`，输出复用 AuthoringTask.author_words/source；旧 author_words 单边输入退役。system 仅 static_block，去掉作者原文的 dynamic_block 与真实结果保持 application 材料；原文和同一来源独立 user。缺失/坏配对失败，不能以 frame/tool/provider ref 代替。无作者的章摘要/盘点调用不改变；不扩展 R05 材料压缩。
- `DialogueContext.to_prompt_text/1` 仍由 `TurnExecutionService` 的专业材料上下文调用，保留其独立职责；判断 Scope 不再消费它，缺失 source_status 不再推定 empty。章节标题视图也只服务其真实专业调用者。
- 专业材料精确字段：创作的 `operation.context_text/revision/planning_mission` 保留原值；质量的 `operation.prose_text/scene_units/facts_context` 保留原值；使命的 `operation.mission_inputs.items` 复用原 ref/group/text；计划的 `facts.chapters` 只接受实有 id/seq/title，观察仍绑定原 observation refs。
- `RequestIR.Operation` 的 `source_refs` 仅表示 Scope 来源关系；`base_refs` 显式表示已供应材料，缺省为空，不从 source_refs 兼容回填。创作/质量只投影 `AuthoringTask.materials` 的 ref 与实有 version；使命只取 `ChapterMissionInputs.items` 的材料 ref；计划只取实际 `facts.chapters`。作者回合、普通来源、目标范围或观察 evidence ref 不因被引用而自动获得 Base/Observation 身份。 Judgment 的 supplied_context_refs 与 scope_source_refs 分别表示实际供应材料与普通来源；append_scope_update/5 显式分开 source_refs/base_refs，删除隐式升格的旧 arity。Prose continuation 的计划及全部观察关联只进入普通来源，不把末六条摘要未提供的计划或证据登记为 Base；同 Scope 的新实际供应材料不能被去重吞掉。
- `omissions` 唯一形状为带非空 `source/reason` 的 JSON map 列表；Scope 内实际对象 ref 同时属于该消息来源和已供应 Base，作者来源不自动升格为 Base 或 Observation。work 版本只取真实 snapshot revision，未知时同时省略 facts 与 message 的版本值。

## 完整执行步骤（一个会话必须交付）
1. 审计已有 RequestIR message/block 可承载结构化事实的能力；先选择现存语义，必要时直接改现役结构，不另设 AppRequest 持久模型。
2. 明确 provenance、work_revision、source_refs、coverage/omissions、当前作者原字节、derived model interpretation 的类型与显示规则。
3. 将章节列表/相关资产信息变为有唯一 ref 字段的结构化事实，避免用标题或作者期望冒充作品事实；确保缺数据=not_read/partial，而非 empty canon。
4. 三 wire 真正消费同一 IR 而非自行拼装另一份来源；负例确认伪 tool observation、错 scope、被覆盖版本不能混入。
5. 增加「仅有 ref ≠ 已读详情 ≠ 当前权威基线」的源头负例：单独来源/目标 ref 只是定位指针；只有当前作品范围内真实读取、版本有效、来源和 coverage 可核验的内容才可进入当前事实。未读、部分覆盖、过期版本或跨作品时，不能把 ref 的推测详情、模型摘要或旧快照提升为当前 Base；有必要时经已有只读探索取得实际观察。

## 反例与禁止行为
章节结构问题中的 desired_visible 与当前 reading visibility 不得同栏；应用字段不可以 user(author) provenance 发给模型。
