# R02 · 当前作品事实与作者原话的源头结构化投影

> **唯一目标**：原有 RequestIR/Scope 消息能够用单一来源表达权威事实、作者目标、推断和观察，杜绝第二 JSON 真源
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)，本卡不记录 PASS/done；[通用单会话协议](README.md) 必读。

## 开工前置
R00 已完成契约方案审查；R01 已冻结基线。若新增 block/字段影响 Frozen 语义先审查并同步唯一契约。

## 当前批次的职责边界
仅现役 RequestIR 纯值/投影、JudgmentProtocol/ContextAssembler 与必要跨 wire 消费者及测试；禁止新增 ModelInteraction DB。

## 完整执行步骤（一个会话必须交付）
1. 审计已有 RequestIR message/block 可承载结构化事实的能力；先选择现存语义，必要时直接改现役结构，不另设 AppRequest 持久模型。
2. 明确 provenance、work_revision、source_refs、coverage/omissions、当前作者原字节、derived model interpretation 的类型与显示规则。
3. 将章节列表/相关资产信息变为有唯一 ref 字段的结构化事实，避免用标题或作者期望冒充作品事实；确保缺数据=not_read/partial，而非 empty canon。
4. 三 wire 真正消费同一 IR 而非自行拼装另一份来源；负例确认伪 tool observation、错 scope、被覆盖版本不能混入。

## 反例与禁止行为
章节结构问题中的 desired_visible 与当前 reading visibility 不得同栏；应用字段不可以 user(author) provenance 发给模型。

## DoD（全满足才 PASS）
生产请求捕获与真实 application scope 来源对账、三 wire 机械等价、作者文字原样、source refs 可校验；已迁移消费者不留旧拼串分支。

## 真实用户效果与证明
一条章数问题与一条结构异议同样可取得真实结构信息且无虚假作者/工具身份。
