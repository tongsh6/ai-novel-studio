# R08 · 意图讨论/纠错/执行语义收敛与原有 prompt 去重

> **唯一目标**：模型能够自然区分事实询问、结构异议、明确效果、质量求证、作者授权，不再误将讨论当执行
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)，本卡不记录 PASS/done；[通用单会话协议](README.md) 必读。

## 开工前置
R05/R07 PASS；B27/B33/B34 原语义矩阵和当前 AuthoringTaskPolicy 规则冲突已查明。

## 当前批次的职责边界
现役 JudgmentProtocol、AuthoringTaskPolicy、专业调用规则、既有单一验证门；不新增关键词路由器。

## 完整执行步骤（一个会话必须交付）
1. 将冲突判例（是否写完的结构状态 vs 文学完成）、能力缺口与作者讨论、内容登记等收敛为单一无矛盾业务规则；已测有效案例不能无证据删除。
2. 使用三轮真实作者原话和反向语义矩阵，确保第二轮回复而不是自动缺口/修改、第三轮按真实能力缺口或合法操作处理。
3. 新增修改已有候选、整章、先别动笔、只保存资料、缺来源、已明确目标、同名歧义等负例；模型只在需补知识时主动探索。
4. 对比同一真实模型与确定性机制，不能用 string.contains 路由和 stub 提升虚假通过率。
5. 局部改写边界：`modification_scope=paragraph_only`、target∈observed_refs、source_refs 真实、`coverage_note` 与 evidence 一致；局部候选不得冒充全章；`change_reason` 必须与 `body` 的可观察改动一致。

## 反例与禁止行为
不得写死‘卷纲’、人物姓名/章节号作为产品逻辑；不让 APP 预分类取代 Agent 判断；禁止用 `content` 代替候选正文，禁止 `change_reason` 与 `body` 实际改动不符。

## DoD（全满足才 PASS）
模型语义 A/B、现有负例库、真正工具调用和 Tauri 作者行为一致；若模型本身失败只能如实留未通过，不签‘完全理解’。

## 真实用户效果与证明
讨论能继续讨论，明确修改才能转到正确能力，用户不需要纠正系统的格式偏好。
