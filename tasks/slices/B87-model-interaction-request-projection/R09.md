# R09 · 能力目录、可建议效果与实际执行 Gate 的单一真源

> **唯一目标**：从当前 AgentRun 的权限/预算/profile 派生真实 authorized 建议集，且执行 Gate 必须同源复查
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)，本卡不记录 PASS/done；[通用单会话协议](README.md) 必读。

## 开工前置
R07/R08；现有 common+application CapabilityRegistry、AgentRunPolicy.allowed_tool_refs、authority_scope、Orchestrator 完成真实调用链审计。

## 当前批次的职责边界
既有 registry、policy 与 application 的授权派生职责，必要只读探索面；严禁新 CapabilityCatalog 主表/独立 Agent。

## 完整执行步骤（一个会话必须交付）
1. 逐字段查 common/application registry 的真实差异（局部结构维护能力不得丢），明确唯一 capability/effect 来源与特殊扩展所在；不存在对象先查证。
2. run 的 allowed_tools、预算、profile、必要前置条件决定可建议 effect；后续执行前重新从当前事实重算 gate，不能只相信 prompt 的 authorized。
3. 报告能力不存在、存在但未授权、版本过期、目标错误的不同结论；catalog 只有有现实消费者时才能按需探索，不能假设已有 capability_lookup。
4. 验证 tool_schema 输出、plan/execute/explore 路径、预算递减、拒绝时无写、无双目录漂移。

## 反例与禁止行为
不让模型修改 risk/authorization；不从未提供的 catalog 提前推断‘没有功能’；不得硬写新的 @judgment_capabilities 副本。

## DoD（全满足才 PASS）
作者同一会话的可见能力与真实 Gate 一致，违法调用会被拒绝；普通回复仍可执行，三 wire toolset 稳定。

## 真实用户效果与证明
Agent 自主求证能力而非被 APP 过度预判；不存在近似操作冒充目标效果。
