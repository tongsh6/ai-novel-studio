# R13 · Critical 确认复用现有 ConfirmationBinding 的完整门禁

> **唯一目标**：合法高风险动作必须在所有模式下等待准确对象/版本/后果的作者确认；拒绝/过期/越界零执行
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)；本卡只承载当前会话执行契约，[README](README.md) 为全部批次共享门禁。

## 开工前置
R10–R12 通过；已存在 ConfirmationBinding、AuthorActionAdmission/Confirmation、GateOrder/ExecutionOrchestrator、ReceiptRepo 的实际路径可复用。

## 真实改动范围
现有确认行为/作者动作/再 gate 入口；不得另建 approval_record 管道或把关键动作变成模型 ask_author 文本即授权。

## 一次会话内必须执行的完整步骤
1. 先将不存在能力/越权/跨作品/错版本的动作 DENY/GAP，合法且 critical 才构造绑定确切 effect、对象、版本、预期影响、可逆性说明的确认。
2. 作者从真实页面同意/拒绝/取消，沿已有 ConfirmationBinding/AuthorActionAdmission 路由，确认后 rebase 当前对象状态/风险/预算/策略再 Gate。
3. 已过期、重复确认、目标被别人改写、并发回答、错误行为 ref 以及多对象不可逆影响都必须 fail-closed。
4. 同意后的合法动作能真实完成、回执与 Canon/阅读投影一致；任何需要先生成候选的链路不能用一次确认对不存在的产物提前采纳。

## 反例与不可逾越的禁止项
不能将跨作品权限从 DENY 升级到 critical；不要让用户点‘同意’直接运行原上轮工具请求而不重新 Gate。

## Definition of Done（不可打折）
Tauri 原生确认/拒绝/过期/重复/跨作品矩阵通过，真实 receipt 和无写状态一致，审计可回放。

## 作者真实使用场景与验收效果
高风险操作询问的内容与真正执行对象一致，明确拒绝永远不会修改作品。

## 交付与恢复纪律
- 先从当前 HEAD 验证依赖、七问、拟新实体查重/复用、old→new 消费者以及需要改的 Frozen 契约；不得根据任务卡推测已经实现。
- 当前批次必须把所述目标、异常与负例、真正消费入口、必要文档/测试/代码/迁移/旧入口删除收在**同一次可验证交付**，不能把必要验收债务交给下一批。
- 按共享 README 跑完整适用门禁与真实用户入口；模型行为须实模证据，确定性替身不可代签。只有真实 PASS 才形成提交并更新 B87 唯一状态源；不可重放/不可执行时如实 FAIL/BLOCKED，保留失败证据与恢复条件。
