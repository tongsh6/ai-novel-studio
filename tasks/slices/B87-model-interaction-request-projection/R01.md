# R01 · 模型请求/响应成本与语义的可靠基线

> **唯一目标**：对真实三轮和可重复多轮场景给出同口径、可审计请求分组/性能/模型判断基线；不先优化
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)，本卡不记录 PASS/done；[通用单会话协议](README.md) 必读。

## 开工前置
R00 事实地图；真实 Provider 调用/JSONL 或可信日志必须合法取得，不把示例数据伪装实际已发生请求。

读取 [B87 §9.4 的固定输入与读侧定位](../B87-model-interaction-request-projection.md#94-r01-输入冻结与读侧证据)：历史三轮日志哈希、行号、用量、3/10/20 轮构造及证据限制。先校验文件哈希；历史日志不冒充当前 HEAD，重复压力样本不冒充 I2 语义独立输入；缺原始 SSE/分组 tokens 必须明确 not_collected。

## 当前批次的职责边界
仅测试/诊断脚本、质量 fixture 和证据文档；禁止生产 Prompt、IR、Provider 的行为改动。

## 完整执行步骤（一个会话必须交付）
1. 从真实 Provider native Chat wire 提取按 System/Tools/Scope/History/Observation/Writer 材料分类的精确字节和可得 Token，复用统一请求事实读取边界，保留 source/hash/版本。成本入口只实现现役实际消费者所需格式，其他格式显式 unsupported；公共 reader 的 Canonical IR 支持仍服务其既有消费者。
2. 冻结三轮真实作者输入与 3/10/20 轮压力构造，分别记录 tool call 与最终作者可见结果，避免把旧异常标为正常。
3. 记录 input_tokens、cached_tokens（输入子集）、output、TTFT、延迟、Provider、model、推理选项、prefix hash、场景覆盖与样本噪声。
4. 输出 BEFORE 仪表/机器可重算 manifest 和负例，后续各批沿用同源口径。

## 反例与禁止行为
不能把 cached_tokens 与 input_tokens 相加；不能以首次请求低成本掩盖跨轮增长；无真实用量时标 not_collected。

启动/准备前的运行安全判断必须取自待用完整数据库的实际运行清单，并核对快照/恢复记录的一致性；JSON声明不是数据库事实。缺失清单不等于已观察到空清单，伪造的空声明不能掩盖非bounded run或非终止task。完整源数据仍原样保留，不靠改任务状态制造安全；原始旧格式证据保持只读，不能为通过新入口回填历史事实。此边界与fixture迁移的执行状态由当前[B84](../B84-web-slow-tests-and-arch-debt.md)维护，不在本卡重复记进度。

## 从目标推导的验收依据

本批服务愿景中的自然创作对话、作者主权与可追溯事实，以及元原则中的最小供给/按需求证/证据闭环。**现有系统表现是待测对象，不是标准答案**。测量正确与产品行为正确分开；二者都必须有与上层目标的映射。

| 场景 / 目标 | 独立预期 | 证据与不得代签的边界 |
|---|---|---|
| 询问当前有几章内容 | 准确区分结构章位、设计态内容与已采纳正文；证据不足时求证或如实说明 | 对账实际材料/覆盖与模型回答；不能因数据库有两条 chapters 就认定“两个完成正文”正确，不能靠标题关键词预制答案 |
| 指出第一章是卷纲的异常 | 讨论或求证异常，不自动把异议升级为修改授权 | 作者输入、真实调用/效果、可见回应；schema 合法不能证明意图判断正确 |
| 明确要求卷纲只在档案显示 | 识别真实目标效果；按已核实能力与授权处理，缺能力如实表达 | 不能拿重编号/无关写作冒充目标完成，不能在实际回执前称已修复；能力目录本身也须核实与设计/真实消费者一致 |
| 长会话与上下文成本 | 作者目标与历史证据连续；记录重复 Scope、探索回流、前缀/成本随轮数的真实变化 | 不用隐式丢历史换低成本；3/10/20 循环是受控压力样本，不代表正常长篇创作或 I2 语义独立样本 |
| 可靠测量 | 按原来源、单位和身份完整记录，可由独立方法复算 | `total - categories` 自洽、实现自己的 hash、PASS 字段或测试数都不能代替材料覆盖与独立对账；缺原始 wire 时只能声称相应日志/投影层的观察 |

基线报告必须对上述目标给出实际观察、符合/偏离/缺证及具体来源；产品偏离不能因“测量完成”销账。R01 不提前修生产行为，也不能只交付工具框架或把获取基线扩成平行产品子系统。测试/fixture/工具的必要性须由本表目标反推。
