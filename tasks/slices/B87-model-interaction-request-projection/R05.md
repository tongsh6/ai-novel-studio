## 完整执行步骤（一个会话必须交付）
1. 从真实请求测量识别常态长角色全文、候选 body_preview、无关历史，并将其替换为可发现的索引/refs/coverage，不静默删除法定义务。
2. 模型判断缺什么，通过现有 prose_search/chapter_read/archive_read/session_adoptions/memory_recall 取得真实观察，并在后续请求可见。
3. 对“章数/质量/已有角色修改/整章与目标段修订/作者文风素材”分别验证需要少读或能取足；已采纳与 tentative 分开。
4. 报告变更前后的请求成本与真实结果，分别说明底座、正文/观察、工具说明及必要协议增量；不凭 Token 缩短宣称文风变好，也不把未预设的“总请求字节必须下降”增设为 PASS 条件。实际重复供给、无消费者规则或错误遗漏仍须在现 owner 修复。

## 反例与禁止行为
不得为了优化让作者重复提供 App 已有事实；整章修订不得只拿单段；不得把历史候选当 Canon。

## DoD（全满足才 PASS）
可信章数等当前事实能直接正确回答；复杂任务能通过现有通用探索追加真实观察，实际进入后续 Judgment/Writer 请求并绑定 used_refs；Writer 必需正文覆盖完整，来源、版本、修改范围与 accepted/tentative 边界真实，相关产品交互与负例通过。单独 ref、目录元数据、partial 或 stale 材料不能冒充详情已读或当前完整基线，作者主动讨论技术 ref 不因词面被拒绝。

按愿景 §2.4，以现有场景的有限真实运行证明模型自主选择必要探索、真实观察回流及结果与证据相容，并让未配置专用 Packet 的作品要素复用同一链；确定性替身只证明接线，不能代签自主求证。继续保留原生页面与真实首个消费者证据，不能以机械门全绿或回答碰巧正确代签。

当前签收按应用责任归因：材料漏供、失真、伪完整、未读授信、范围扩张或作者实际无法取得结果仍是本批缺陷。正确且充分的材料与约束已进入真实请求后，独立的格式服从、推理或文学偏差如实保留，按 R08/R18/R19 的原职责承接，不单独否决 R05，也不据此新增专用提示、词表或模型评审循环。六类原场景、旧 FAIL/partial/未执行事实和原始证据不改签；当前结果按 B87 §16.1、§16.39 核账，本次边界修订不自动宣布 PASS。
