# R14 · Full 授权委托的最小必要持久范围与撤销

> **唯一目标**：作者委托必须可核定作品、操作、effect、目标、时间、撤销及审计来源，在过期和越权时立即失效
> **状态真源**：[B87 总计划](../B87-model-interaction-request-projection.md)；本卡只承载当前会话执行契约，[README](README.md) 为全部批次共享门禁。

## 开工前置
R11/R12/R13 通过；确认 existing WorkSession/作者动作/审计/Receipt 无法胜任何种稳定委托语义后才可新增最小字段/对象。

## 真实改动范围
优先扩展当前作用域配置及作者动作/回执存储；确实不能表达安全生命周期时允许一项经审计的新最小实体，不建通用授权中心。

## 一次会话内必须执行的完整步骤
1. 出具与现有持久模型的逐字段对照：issued_by/source_turn/target_work/capability/effect/target/version/expiry/revoked_at/range/budget，裁决 reuse/refactor/truly-new。
2. 从真实用户设置入口进行委托创建/变更/撤销，后端检查身份和产品模式，所有写入可追溯并事务一致。
3. 对过期/已撤销/跨作品/target 改变/冲突版本/并发撤销与启动中的 run，在真正写入前再次验证有效委托；fail-closed。
4. 委托事实可被 R15 的采纳门消费；撤销后任何后续写入不能复活旧授权，UI 能展示当前授权有效范围。

## 反例与不可逾越的禁止项
不能把 mode=full 当成无限制 delegation_ref；不得先建通用授权表族、再回头找消费者；绝不为了通过测试放宽撤销语义。

## Definition of Done（不可打折）
真实 UI 创建/撤销/恢复链路、唯一有效范围及撤销原子性可证明，模型不能签发授权，无旧权限泄漏，审计齐全。

## 作者真实使用场景与验收效果
作者可以明确知道自己委托了什么、可以随时撤销，而不是默认永久自动写书。
