# scripts/lib/native_ui/ — 原生 Tauri 窗口外部驱动（验收 harness）

本目录提供**外部系统 UI 驱动**：通过 macOS Accessibility（AX）读取真实 Tauri 窗口的用户可见语义，
并用 AX 动作/CGEvent 输入操作真实窗口。产品代码不读取本目录，也不为此新增任何验收感知逻辑
（见 `docs/engineering/scenario-acceptance.md` 红线）。

## 组成

| 文件 | 角色 |
|---|---|
| `ax_cua_core.swift` | AX/CGEvent 驱动的全部实现：读命令与 `resolve / startup / probe / input`；批次输入携带 target（run_ref/app_path/executable_path/PID/generation），在每次投递/分块前核验精确路径、PID、前台、AX 信任、CG post 权限与预期焦点。`probeEvidence` 只组装观测（target/resolution/permissions/**单一 `frontmost` 观测**/focus），不产出 activation；`operationEvidence` 保留本次 input 操作自己的 `activation`/method/focus 结果，再补操作后 permissions 与 `frontmost_after`，不拿 probe 事前快照顶替。所有键盘/鼠标/滚轮事件用 `postToPid`；事件创建数不足时显式 `event_creation_failed`，不把“函数返回”当文本到达。激活等待用有界主 run loop common-mode 轮次（default mode）推进，独立观测 frontmost PID/isActive，并用实际时钟计 elapsed。`dump/dumpall` 节点记录 `enabled` true/false/null 与 `focused`。 |
| `ax_cua.swift` | 可执行入口（`@main`），只调用核心的 `runMain()`；与核心分开后行为测试可编译同一实现而不启动 CLI。 |
| `input_target.mjs` | 目标归属/输入授权纯策略：只从本批 `ready.app_path` 推导唯一 executable；PID 必须是 `pid_t` 范围内的正整数，首次 bind 只接受未绑定或同 PID 幂等，不同 PID 只能显式 `relaunchTarget` 换代。`probeObservation` 是 Swift probe JSON 的单一解析边界：只保留观测字段，丢弃旧 producer 的 `activation`；`operationResultFacts` 只取 input 操作返回的 `activation`/`focus`/`permissions`/`frontmost_after`。`authorizeInput` 的非 activate 前台授权只消费顶层 `frontmost.{pid,bundle_identifier}`，缺失/非法/非目标/归属冲突都拒绝；不存在 `activation.frontmost_pid` 回退链。权限只接受显式 boolean true，`enabled=null` 但 `AXValue` 明确可写仍为合法正例；`focus` 操作不要求事前已聚焦，`insert` 仍要求实际预期焦点；`splitUtf16Chunks` 不拆代理对。 |
| `input_boundary.mjs` | 单一输入门/投递边界：先 probe/授权/落盘 attempt，再调用注入的真实 event adapter；拒绝或证据写失败时零投递。authorize 只取 probe 的观测字段（含 `frontmost`），target/request 始终来自构造绑定与本次调用；`attempt` 记操作前观测，`result` 记本次 input 返回的 activation/frontmost_after/focus/permissions。adapter 失败只输出稳定 reason 与 code/signal/status/output_length，不携带 argv/message/request/facts 正文。`makeJsonlSink` 写 `native-input-events.jsonl`，只记录目标路径/PID/激活/frontmost/焦点/permissions/gesture/长度，不记录输入文本内容。 |
| `build.sh` | 按需编译 `ax_cua_core.swift + ax_cua.swift` 到 `artifacts/tools/ax_cua`（gitignore 产物；需要 Xcode command line tools 与「辅助功能」权限）。 |
| `driver.mjs` | 高层封装：只读 `dump/findByText/screenshot/waitUntil/writeAX` 可接 target 或通用应用名；真实输入 `click/clickAt/scrollAt/focus/typeText/pressKey/activate/setValue` 必须接已绑定 target，未绑定直接 `target_unbound`，不再按 PID/名字自动找入口。`bindRunningTarget` 只供启动/显式 relaunch 后一次性绑定；`cua`/`parseAdapterJson` 把 exec 失败与坏输出转成安全 reason。`Step` 继续写 B37 分型等待账 `native-driver-commands.jsonl`，与 `native-input-events.jsonl` 分离。 |
| `workbench.mjs` | 真实工作台动作：`launchApp` 从 ready 构造 target、启动后绑定实际 PID；`sendMessage` 只接受绑定 target。其余档案/阅读/采集辅助沿用。 |
| `scenario_driver.mjs` | B61/B62/B71 场景驱动共用运行时：`NativeScenarioHarness` 每次批次用 ready.app_path/run_ref 构造 target，启动后绑定实际 PID；每次输入由同一 target 重新核验；仅 restore 分型的显式 relaunch 会换代重新绑定。`openApplication()` 只 open 本批精确 app_path，供 `rawLaunchApp`/`rawCloseAppAndRelaunch` 共用，测试可覆盖以验证启动观测顺序而不启动真实窗口；`rawLaunchApp` 在首次 activate 前后各落一次只读 `startup` 观测（`launch:before_activation`/`launch:after_activation`，含 `is_finished_launching`/`ax_window_count`/`has_ax_window`/`has_ax_web_area`），attempt 先于 activate 落盘，观测错误折叠为事实而不阻断激活。`rawTypeAndSend` 先激活/聚焦同一 composer path，逐块投放并对 AX value 做一次有界严格相等观察，再点击真实发送并等待真实 WS；不再自动重试同一段输入。作品菜单点击/输入均走 target，失败按原因落盘。 |
| `process_observation.mjs` | 原生批次 owned 进程观测的唯一适配层（`native_ui_wait` 与 `native_app_ownership` 共用）：严格优先 setuid 的 `ps`；仅当执行环境明确拒绝（EPERM/EACCES/ENOENT，或 spawn 失败 message 明确为 operation not permitted / no such file）时才退化为 `pgrep -f <精确 realpath pattern>` 候选发现 + `lsof -p <pid> -a -d txt` 的 txt 实际路径 realpath 精确相等判定；pgrep 只发现候选，绝不按进程名/前缀归属；lsof 也被拒绝时显式失败而非静默当作空集合；其它 ps 错误不降级。实际方式与 fallback 原因由调用方写入 `wait-stats.json` / `native-app-cleanup.json` 的 `process_observation: {method, fallback_reason}`，不伪装成 ps 观测，也不放宽 cleanup 的 `remaining=[]` 断言。 |
| `scenario_evidence.mjs` | B61/B62 场景证据核验共用部分（只读）：ready/ui-complete/等待账/截图/provider/transport 通用断言、生产源码指纹（tracked+untracked、遵循 `.gitignore`、按既有 productPath 去重）、只读 DB 生产表计数、WS 帧落盘、summary（含 `behavior.assertions`）写法。共享请求证据边界：`requestIdentity` 是 `user_message` 与 `author_action` 共用的方向/at/join_ref/request_ref/topic 校验，`requestReplies` 是两者共用的 phx_reply 读取；`turnFacts` 的 ACK 必须匹配作者消息自己的请求身份与不早于发送时间，缺失/多义 ACK 由消费者显式失败，不在三个场景各补黑名单；成功响应形状与 `run_id` 仍由消费者核验。broadcast（`agent_event`/`turn_result`/`action_result`）的真实 `join_ref`/`request_ref` 为 `null`，由 `broadcastFrames` 按 owning `topic`+方向+时间+实际 run 绑定，不要求广播 ref 等于作者请求 ref。 |
| `authoring_planning_evidence.mjs` | B71计划/重规划消费链的纯核验：实际请求严格前缀与阶段工具、canonical调用ID顺序/结果闭合、计划版本与预算；Why前后按真实事件发生时间判定无模型调用。由native_b71_evidence及其Node正反例测试消费。 |

## 输入证据与失败边界

- `native-input-events.jsonl` 是独立输入事件账（不是 B37 `native-driver-commands.jsonl` 等待账）。每行含
  `run_ref / target.{app_path,executable_path,pid} / generation / gesture / frontmost / focus.{role,path,desc,enabled,
  value_settable,matches} / permissions.{ax_trusted,post_access} / result.{ok,reason,method,delivered_chunks}`
  与输入长度；`attempt`/`rejected` 的 `frontmost` 是 probe 操作前观测，`result` 的 `frontmost` 是本次 input
  返回的 `frontmost_after`。`activation.{requested,returned,confirmed,frontmost_before,frontmost_after,waited_ms}`
  只出现在 `activate` 的 `result`，来自真实 input 返回，不由 probe 预置；`result` 的 `focus` 也只取本次操作
  返回的焦点事实。不写输入文本。
- 除 `activate` 自身以 input 操作结果确认外，没有绑定 target、路径/PID 变化、多义进程、
  `frontmost` 缺失/非法/非目标/归属冲突、焦点不匹配、AX/CG 权限不足、证据写失败时，边界直接失败且零投递；
  不请求/修改系统权限，不换渠道绕过。前台事实只有顶层 `frontmost` 一个来源，不存在
  `activation.frontmost_pid` 回退。
- PID 绑定是生命周期：启动后由 `bindRunningTarget`/`bindBatchTarget` 一次性持有；输入入口不再自动解析 PID，
  `bindTarget` 对已绑定不同 PID 抛 `target_already_bound`，只有显式 relaunch 才换代。
- 只读 `dump/dumpall` 保留通用应用名用途；批次输入不再有按名字/`exact.first`/`partial.first` 的 fallback。
- 读路径与动作分离：`dumpNodes`/`capture` 只读 AX，不 activate/key/click/type；正常交互需要
  关闭 tooltip 或恢复前台时，由命名的 `recoverInteractionSurface`/`activateForInteraction` 显式执行并
  落 `interaction_recovery`/`interaction_activation` 日志，不藏在 dump/read 里。
- failure 采集只观察同一本批 target/PID：`failure.json.observation` 记录 `startup`（真实
  `is_finished_launching`/`launch_date`/`activation_policy`/`is_hidden`/`is_active` 与
  `has_ax_window`/`has_ax_web_area`）、`ax`（不可得时为 `ok:false` + 原因；可读但无主窗口时
  `main_window:false`）与 `screenshot`（只截 target，不做整屏兜底）。采集失败只写原因，不覆盖原
  `reason`，也不为补截图改变现场。`failure-observation.json` 始终单独落盘，避免监督进程先写
  `failure.json` 时观测因竞态丢失；`failure.json.reason` 不被覆盖。
- `target_bound`、`launch_activation_attempt`/`launch_activation`、`relaunch_activation_*` 与
  failure 观测都带本批 target/PID 和时间；启动事实仅观测，不构成 ready gate、超时或重试。
- 批次监督与 cleanup 的 owned 进程观测统一走 `process_observation.mjs`：优先 `ps`；只有 setuid `ps`
  被执行环境明确拒绝时才用 `pgrep -f` 候选发现 + `lsof -p -a -d txt` 实际路径 realpath 精确归属；
  实际方式与原因写入 `wait-stats.json` 与 `native-app-cleanup.json` 的 `process_observation`，
  不把 fallback 说成 ps 观测；fallback 下仍要求 `remaining=[]` 且只按本批 executable 精确归属。
- runner 在 app 启动前只打印 bundle/driver 资源 ready，不再声称窗口已就绪。

## 使用约束

- 需要桌面解锁且系统授予「辅助功能」权限；一次只驱动一个原生批次（端口 4657/4661 单占）。
- 只操作产品真实入口与可见语义；不得新增 data-testid/隐藏钩子/验收 env 分支。
- 真实模型批次仍遵守单槽串行、加载前记录、结束卸载并验证为空；长跑用 detached 监督。
