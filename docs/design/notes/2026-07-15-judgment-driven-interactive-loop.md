# 判断驱动交互循环（探索）：从"计划伪装"回到真循环

> 状态：讨论备忘（不冻结 schema、不授权实现）。结论需升级为新 ADR（建议 ADR-0025，
> 大修 ADR-0023 适用域）+ contract 修订 + slice 后方可实现。
>
> 来源：2026-07-15 用户拍板（两次澄清）。①"消灭形式主义"（对话 profile 恒定四步
> 计划起草零信息量）；②方向级纠正：**要的不是更省的固定管线，而是真循环**——
> "初始会话 → 模型判断 → 判断下一步 → 执行 → 或者等待用户裁决"；③关键澄清：
> **计划由系统能力 + AI 判断制定，但不是每次都做计划——"是否需要制定计划"本身
> 是 AI 根据情况的判断**（不按场景预分配）。
>
> 上游：ADR-0021/0022/0023、`notes/2026-07-04-agentic-loop-plan-driven-execution.md`、
> 46§9.4/9.5（体裁与文档流化）、ADR-0024（S1-S7 决策面）、SI-model-behavior-contracts。

## 1. 用户要的形态（目标循环）

```
作者输入（初始会话）
   ↓
【机械】组装当前作品上下文（读库，永不问模型）
   ↓
【模型判断 ①】理解意图 + 判断本轮形态（叙事流式给作者）
   ├→ 简单 → 直接回复 / 单动作执行（不制定计划）
   ├→ 复杂 → 基于系统能力目录制定计划 → 按计划执行
   │        （执行中判断②仍可修订计划或停下等作者）
   ├→ 需要澄清 → 停，等待作者（S4）
   └→ 高风险 → 停，等待作者确认（S3）
   ↓
【执行】生成回复 / 经 Orchestrator 门禁调工具产出待采纳草稿
   ↓
【模型判断 ②】观察结果，判断下一步（叙事可见）
   ├→ 目标已达成 → 收束（run completed）
   ├→ 还需继续 → 做下一个动作（有计划则推进/修订计划）
   └→ 需要作者裁决（选候选 / 采纳 / 改方向）→ 停，等待作者（S1/S2/S5）
   ↓
（循环，直到收束或停在作者处）
```

核心特征两条：**判断分布在全程**——每个动作之后模型看结果、决定继续或停下，
"等待用户裁决"是循环的一等出口（S1-S7，ADR-0024 已冻结）；**计划按需涌现**——
计划由系统能力目录 + AI 判断制定，但"是否需要计划"本身是判断①的输出之一，
简单请求不做计划直接执行，app 不按场景预分配"计划型/循环型"（那是另一种写死）。

## 2. 与 ADR-0023 的关系：不是回退，是修正判断的位置

ADR-0023（2026-07-04）从"每步问模型"迁到"计划驱动机械推进"，动因三条（有实测）：
调用经济学（7 次/轮、40-65s，一半是问"下一步"且答案恒定）、协议鲁棒性（坏 JSON
灭 run）、判断力（只见一行摘要）。**这三条反对的是"把确定性搬运也交给模型"——
该立场保留。**

本方向修正的是另一件事：ADR-0023 把**创作决策**也压扁进了"开头一次性起草计划"。
对话/交互式创作场景中，"下一步该做什么"取决于刚发生的结果与作者意图，本质是
逐步判断，把它预写成计划要么是恒定管线的伪装（对话四步），要么频繁触发修订
（D 系被当作常规路径用）。

**计划按需（本 note 的核心主张，用户 2026-07-15 澄清后修订）**：

不按场景预分配"计划型/循环型"（app 预分类是另一种写死）。计划是判断①的
可选输出：模型认为任务复杂（多步、跨章节、批量）时基于系统能力目录制定计划
（此时计划是真信息，作者可预览的路线图，UI 显示步骤与进度）；简单请求不制定
计划，直接判断→执行→判断。已制定的计划仍是活文档（判断②修订，D 系机制沿用）。

N-PLAN 不变量随之改写："**当存在计划时**，计划必须由模型制定并维护，app 不得
预制计划轨道；**是否制定计划**由模型判断，app 不得强制起草也不得预分类"；
无计划的循环轨道 = 逐次 judgment 记录（judgment 事件链），同样禁止 app 预制
创作决策（机械准备步除外）。

## 3. 三类节点的精确定义（防止再次滑向两个极端）

1. **机械准备**（app 代码，0 模型调用）：组装上下文、快照读取、投影刷新。
   判据：输出对相同输入恒定、不含创作判断。
2. **模型判断**（真决策点，模型调用）：
   - 判断①（意图+动作）：作者输入后——本轮要做什么？覆盖原路由 + frame 意图
     理解语义（**路由并入判断①，不再独立调用**）。
   - 判断②（观察+续行）：每次执行完成后——达成了吗？继续什么？要停给作者吗？
     复用 ADR-0022 `evaluation_of_last` 思想与 D 系观察结构；对"简单回复"路径
     允许协议内联（见 §4 方案 B）免独立调用。
3. **用户裁决**（S1-S7 决策面出口）：澄清/确认/候选/采纳/方向——循环的正常暂停态，
   run 进入 awaiting_author，作者输入后循环继续（或新 run 衔接，见开放问题 3）。

Orchestrator 执行门禁不变：判断①/②只有建议权，工具执行仍逐动作过 gate
（ADR-0003/0004/0005/0021 全部保留）。

## 4. 判断调用的协议设计（两段式约束下的三个方案）

约束：强制 native tool call 时 content 无流式字节（MBC 实证），而"run 开场
静默"是最初主诉——判断①必须有流式叙事。

- **方案 A：判断两段式**（直接沿用现协议）：call1 自由输出判断叙事（流式），
  call2 强制 tool call 输出动作结构。对话轮 = 判断①(2) + 回应(1) = 3 次
  （现状 4 次：路由并入判断①省 1）。创作轮 = 判断①(2) + 工具(1) + 判断②(2 或 1)
  = 4~5 次（现状 4 次，判断②是否两段是主要变量）。
- **方案 B：回复内联**（推荐进一步探索）：判断① call1 的自由输出协议约定——
  若模型判断"直接回复"，则叙事之后**接着输出回复正文**（同一次流式调用），
  call2 仅结构化动作与坐标（轻量）。简单对话轮 = 2 次调用（判断①两段合一产出
  回复），比现状省一半。判断②对直接回复路径免除（回复即终点）。
  创作轮：执行调用（writer）的结构尾巴/arguments 携带 `evaluation_of_last` 式
  自评 + 建议动作（ADR-0022 已有此结构），判断②仅在自评不确定或偏离时独立调用
  ——正常路径创作轮 = 判断①(2) + 工具(1，含自评) = 3 次。
- **方案 C：单调用判断**（依赖 MBC 分岔 A）：判断① = 1 次强制 tool call，叙事走
  arguments.author_reasoning（已有 provenance 机制）——但无流式字节，违背开场
  体验主诉。**仅作为 thinking 系模型（qwen 空 content）的降级路径**，不作主线。

调用经济学对比（对话轮 / 单候选创作轮）：

| | 现状（计划驱动） | 方案 A | 方案 B |
|---|---|---|---|
| 简单对话 | 4 | 3 | **2** |
| 单候选创作 | 4 | 4~5 | **3** |
| 判断真实度 | 起草时一次 | 每动作 | 每动作（自评内联） |

## 5a. 探索能力域（2026-07-15 用户确认"必须"）

判断循环给了探索的结构位置（判断①/②可产出探索动作、`explore` 步骤类型、
`exploration_observed` 事件族已在契约中），但当前探索工具面薄：AI 只能"整读"
（全阵容/全 stats/机械上下文预取），不能"检索"（按需查细节）。**"AI 判断
'我需要什么'后去拿"是循环的必备能力翼**——探索结果决定下一步，这正是循环
优于预写计划的典型场景。

目标形态示例：

```
作者：「给沈砚写一场和云栖的对手戏，放第 16 章」
判断①：需要先确认两人关系现状与上次交锋
  → 探索动作：查沈砚×云栖关系记忆 + 检索两人共同出场章节
  → 观察：第 9 章有账单对质，关系是互相试探
判断②：信息足够 → 写作动作（携带前文证据）→ 起草 → 停下等作者采纳
```

三层补齐（随 ADR-0025 定框架，工具箱独立 slice 排期）：

1. **检索工具箱**（只读、细粒度）：`search_prose`（全文/按章检索）、
   `query_character_scenes`、`query_foreshadowing`、`query_timeline` 等；
   全部只读，Orchestrator 低门禁放行（记预算、不需确认、不写事实）。
2. **作品事实索引**：已采纳事实（正文/角色/伏笔/时间线）建检索索引；
   起步用 SQLite FTS，不预设向量库（YAGNI；混合检索留给后续按需）。
3. **探索预算**：循环内探索上限（如 `max_explore_calls`）纳入既有预算
   backstop；无新信息的连续探索命中 no-progress 停机语义。

与 `ai-learning` 项目的交汇：其 Phase 2（设定库/剧情记忆/hybrid search 作为
写作 Agent 检索系统）与本能力域同题，检索设计可互相反哺。

### 5a.1 外部翼：网络搜索（2026-07-15 用户拍板加入）

内部检索之外，探索还需**向外**：历史向小说的朝代制度/服饰/官职/地理、现实
题材的行业细节——AI 判断"作品设定需要外部底料"→ 搜索 → 整理为**带来源出处
的世界设定候选** → 停下等作者裁决（S2 采纳）→ 采纳后进作品事实库，此后创作
携带这些设定工作。

领域语义三条（与既有权力结构对齐）：

1. **搜索结果不直接成为作品事实**：外部资料只能产出 tentative 设定草稿
   （world_setting / 规则 / 时间线候选），采纳权在作者——史料可能错漏，
   这道门是领域必需。
2. **来源可溯**：设定候选携带出处引用（URL/文献名），进 trace；作者可据此
   判断可信度。与 N-NARR 可审计精神一致。
3. **网络边界**：本产品其余部分本地优先；搜索 query 会把作品信息带出本机——
   搜索行为必须作者可见（活动行「正在搜索资料…」）、query 全文进 trace、
   网络访问需要显式授权边界（默认开关/逐次确认，ADR 阶段定）；搜索服务走
   provider 抽象（SearchProvider，与 LLM gateway 同构，可换实现）。

工具形态：`web_search`（只读、出站）+ `compose_setting_from_sources`（整理为
带引用的设定候选）。探索预算对内外统一记账。

## 6. 鲁棒性与预算（继承 ADR-0023 的教训，不重蹈 7 月 4 日之前）

- 判断调用坏结构 → 既有纠错重试一次（携带失败片段）；再失败 → awaiting_author
  （不灭 run）。
- 循环上限：`max_steps` / `max_provider_calls` / `max_pending_artifacts` 预算
  backstop 原样生效；判断②连续"继续"而无新进展 → 既有 no-progress 停机语义。
- 完成信号：判断②的"目标已达成"必须显式（结构字段），禁止靠措辞猜测。

## 7. 建议 CP 路线（均需六问 slice + 用户批准）

1. **CP0**：本 note 升级 ADR-0025（判断驱动交互循环 + N-PLAN 适用域改写 +
   判断协议选型 A/B）；ADR-0023 标注适用域收窄注记。
2. **CP1**：conversation profile 迁判断循环（方案 B：判断①两段 + 直接回复内联）；
   路由并入判断①。验收：简单对话 2 次调用、叙事流式、judgment 事件链完整。
3. **CP2**：单候选创作 profile（character_design 等）迁循环（工具执行 + 内联自评 +
   判断②按需）；候选产出后停 S1/S2 裁决。
4. **CP3**：prose/修订迁循环；D 系信号在循环语义下回归验证。
5. **CP4**：计划按需全量落地——判断①"制定计划"分支协议（计划结构沿用
   AgentPlan、基于能力目录）、UI 真计划步骤/进度恢复显示；验收资产/N-PLAN
   driver 全量迁移。
6. **CP5**：探索能力域·内部翼（§5a）——作品事实索引 + 检索工具箱 + 探索
   预算；判断①/②接入探索动作。可与 CP2/CP3 并行推进（只读、低风险）。
7. **CP6**：探索能力域·外部翼（§5a.1）——SearchProvider 抽象 + web_search
   工具 + 带来源设定候选链路 + 网络授权边界。依赖 CP5 的探索动作框架。

## 8. 开放问题（ADR 阶段收束）

1. 判断②内联自评（方案 B）在弱模型上的可靠性——需要 MBC 探针先行（复用
   tool-call-compliance 模式）。同样需要探针验证：判断①"是否制定计划"的判断
   质量（弱模型会不会对简单请求乱开计划/对复杂任务不开计划）。
2. 判断①合并路由后，profile/能力集的声明方式（authority_scope 仍按任务类型分账？
   预算怎么定档？）。
3. awaiting_author 后作者输入的续行语义：同 run 恢复循环，还是新 run 携带裁决
   上下文衔接？（与 S7、durable resume 交叉。）
4. 交互循环的 judgment 事件命名与 46§9 事件族契约。
5. 进度行在循环场景的表达（无预定 m，"第 n/m 步"失效——动作计数？还是仅活动行？）。
6. 外部搜索的授权粒度（作品级开关 / 逐次确认 / 完全信任）与 query 脱敏策略；
   搜索 provider 选型（本机代理环境下的可用服务）。
