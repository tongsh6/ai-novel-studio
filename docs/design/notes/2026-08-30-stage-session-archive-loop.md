## 2. 三层缺陷（D8 族）

- **D8a 能力真空**：judgment 能力表 = 5 个「产出待采纳候选」+ 1 个只读
  `work_archive_read`。「把已讨论定稿的内容写入档案」这一高频作者意图**没有任何
  承接路径**——产品的写入语义是「候选→作者采纳」，但作者说「存档」时若无候选在场
  （或不知道要去采纳），链路就断。
- **D8b 命名诱导**：`work_archive_read` 的「archive」与「存档」字面撞车。模型在
  「明知要写入、可选项里没有写入」时选择了名字最像的只读能力——与 MBC 判例同构
  （能力语义靠名字传达给模型，名字错位=判定错位）。
- **D8c 静默失败 + 引导复踏**：execute 轮 run 只读跑完即完成，**没有向作者承认
  「我没有写入能力」**；16:29 的 reply 甚至说「说明尚未执行**并提示可随时触发存档**」
  ——把作者引回同一个坑。谎报族行为学新例：承诺执行 → 实际只读 → 不认账 → 劝再试。

另注：16:02 的 world_building 候选一直挂着待采纳——作者「存档」的正确出路
（引导采纳该候选）三次 meta_discussion 均未指出，`candidate_directions` 全程为空。

## 5. 根本性分析（2026-08-30，作者批评「补丁式」后重挖）

### 根 1：作者内容不可物化——作者主权倒挂（架构级）

候选（`TentativeArtifactSet`）在全仓只有两个产生源：`artifact_assembler`（从
tool_result 组装）与 `fact_inventory_service`（盘点 provider 产物）——**全部是模型
工具的产物**。作者在对话里亲手提供的内容（本例：完整大纲）只有一条去路：作为 prompt
上下文被消费。它**永远成不了候选、永远进不了档案**，除非模型「再创作一遍」。

这与产品的立身语义冲突：全系统以作者主权为轴（author_action、作者裁决、作者采纳），
写入的唯一大门是「作者采纳」——但**门里只放模型的东西**。作者说「把我给你的大纲存档」
时，他在行使主权，而系统没有对象承载这个主权动作。「存档」死循环只是这个洞第一次被
真实作者踩到。

### 根 2：判断协议的封闭世界——没有「做不到」的出口（协议级）

`judgment_protocol` 的动作全集 `~w(reply execute plan await_author)` + explore；
execute 的 capability **必须在能力目录内**（M0/M2 判例把越界/null 都打成重试）。
于是当作者意图落在目录空白处，模型面临的不是「承认缺口」而是**被迫从错误选项里挑
最像的**——本次挑了字面最近的 `work_archive_read`。reason 原话「实际写入档案」
证明模型清楚意图，是协议不给它说「我没有这个能力」的结构化出口。

今天是「存档」，明天任何未建模意图（导出、删除、重命名、迁移…）都会在同一个机制上
再现——**这不是能力表少一行的问题，是协议假设「目录永远覆盖意图」**。

### 根 3（贯穿判据）：缺口处硬补，而非诚实——与 D7 同根

D7：数据缺口（authoring_intent 缺失）被硬补成默认值（覆盖）。
D8：能力缺口（无写入能力）被硬选成最近邻（只读）。
同一设计反射：**系统在信息/能力缺口处不承认缺口，用默认值或最近邻填平**。填平的
代价由作者承担（被覆盖的正文 / 五连击死循环）。应提炼为设计原则：**缺口诚实律**——
缺口处的正确行为是显式承认 + 给出最近可行路径，而不是猜。

### 修根方向（结构刀，待拍板）

| # | 刀 | 内容 |
|---|---|---|
| **R1** | 作者内容物化通道 | 让「作者提供的内容」可以成为候选：judgment 判「作者要求登记其内容」时产出**以作者消息字节为源**的待采纳候选（内容不经模型重写；I1 因果绑定到作者消息而非 provider 响应）。走既有采纳链，采纳契约零改动——补的是候选的**第二个合法来源** |
| **R2** | 判断协议能力缺口出口 | 决策枚举增加结构化「capability_gap」（或 reply 的结构化子型）：必带「缺什么」+「最近可行路径」（如指向在场待采纳候选）。协议级改动，涉及 frame/judgment 契约与 UI 呈现 |
| **R3** | 缺口诚实律入档 | 把「缺口处显式承认、给最近路径、不猜」提炼为工程原则（与 D7 的 fail-safe 判据合并），进 VS-00G/engineering，作为后续能力/协议设计的红线 |

R1 治「这个意图为什么无处安放」，R2 治「无处安放时为什么变成错误动作」，R3 防同族
再犯。①②③ 可作为 R1/R2 落地前的临时止血，但不应单独作为收口。

## 6. 病理层（2026-08-30，作者二次批评「还不够深刻」后重挖）

把本产品的全部病史摆在一起——D7（字段缺失→覆盖正文）、D8（无能力→误选只读）、
M0（intent 填中文短语→吞成 nil→覆盖正文）、M0（自造能力名）、M2（capability null）、
D1（真空+禁令→「主角」41 处）、MBC（防 gpt-oss 的禁令逼 qwen 镜像失败）、坐标回退、
幽灵任务——它们不是一族缺陷，是**同一个病理的不同切面**：

### 病理：校验体系与价值体系错位

**所有机器防线都守形式，所有真实失败都发生在语义。**

本次「存档」是最纯的标本：同一个 tool-call 里，`reason` 写着「把大纲**实际写入
档案**」（理解层，全对），`capability` 填了 `work_archive_read`（行为层，全错）——
**理解与行为在同一响应里自相矛盾**。而系统怎么处理？已核验：`reason` 字段全链
**零校验、只透传展示**（dialogue_planning_service:1034 原样放进结果），系统只消费
结构化字段。矛盾从眼皮底下穿过，没有任何防线负责看见它。

这不是疏忽，是体系性的：本产品积累的全部防线——schema/enum、能力目录白名单、
@writing_intent_values、I1/I2/I3 不变量、B9 词表、D7 的键存在性——**全部是形式
合法性校验**。它们能回答「字段合法吗、字节相等吗、词在不在表里」，不能回答
「这个行为忠实于作者的意图吗」。语义忠实性无人看守，因为它难以机器验证，于是被
体系性留白。每次失败后的修复又是「再加一条形式校验」（required、白名单、默认值、
enum），而下一次失败照例住在形式层之外——**这就是为什么补丁永远追不上缺陷**。

更尖锐地说：模型是语义强、结构弱的器官；本系统把校验重心全部压在模型最弱的一侧
（结构字段），把模型最强的一侧（reason/叙事里的语义推理）当废气排掉。「意图用 AI
非关键字」的纪律只走了半程——判定用了 AI，**对判定的对账没有用 AI**。

第二个切面：**作者意图被当作一次性输入消费，而不是待满足的义务**。turn 是原子，
turn 之间没有「未竟事项」。作者五次重复「存档」，系统五次从零判定——判定分布
稳定，于是稳定地错。「同一诉求连续五次未被满足」是全场最显眼的信号，而系统没有
任何状态能注意到它：run 内有 goal，**跨 turn 的作者目标不存在**。这个产品是
对话系统，还不是目标系统。

### 病理级修向（供拍板——不是加防线，是把防线从形式层迁到语义层）

| # | 刀 | 内容 |
|---|---|---|
| **P1** | **语义对账（self-consistency 守卫）** | 把模型的理解层从展示品变成校验输入：judgment/plan 的 reason 与所选 action/capability 做一致性对账（规则先行：reason 含写入语义 × capability 只读 = 矛盾拦下；后续可升 AI 对账）。M0/D7/D8 三案在此一网打尽——它们的 reason 全都写对了 |
| **P2** | **作者义务状态** | 作者的显式诉求成为一等状态（跨 turn 义务），只有作者确认满足才关闭；同一义务重复未满足即升级（诚实告知+候选路径），五连击在第二击终结 |
| **P3** | **产出对账闭环** | execute 完成时回答「本产出满足了作者的哪个义务」——答不上来=诚实上报，不静默完成 |

R1/R2/R3 仍成立，但它们是 P1/P2 的实例化：R2（能力缺口出口）是 P1 对账发现矛盾后
的出口之一；R1（作者内容物化）是 P2 义务的一种满足手段。先立 P，R 随 P 落。

## 7. 成文哲学对照（2026-08-30，作者要求按真实设计文档核对，不凭记忆）

成文哲学的权威出处：`00`§1/§2（v3 存在理由、总愿景八维、会话结构内核、AI 引导式
创作及其边界）、`docs/design/README` v3 指导原则 11 条、`00`§10 反模式、`01`§3
（Dialogue-first、四类引导、三层 contract）、`VS-00D`§3 决策分权（「AI 参与创作判断；
Agent 约束和取证；Orchestrator 裁决执行；作者保留创作主权」）、`08`（要素×层级×三态、
三态对账）、`quality/32`§6（作品定位/主角/主线：生成候选可自动、写入需 adoption）。

对照病史（D1-D8、M0-M10c、判例族），落差分**两类**：

### A 类：哲学已成文，实现断头——且多数是文档**自我登记过**的差距

| 成文承诺 | 出处 | 实弹 |
|---|---|---|
| 结构引导「把想法整理成卷/章/场方向」+ 执行引导「在下一步之间提出建议」 | 01§3.2 | D8：作者立项（32§6.1 的标准场景）走到「存档」这最后一步，引导链断头——正确答案（引导采纳 16:02 候选）在哲学里写着，实现没接 |
| 「没有上下文时必须暴露缺失」「AI 不能声明对象真实存在」 | 01§3.2 / VS-00D§3 | D8c 静默完成、劝作者再试——暴露缺失义务失守 |
| 三态对账：「两态都有、不对账=偏离静默累积，崩溃只是延迟到来」 | 08§5.2/5.3 | NEM-GAP-06「三态对账无一等机制」**至今未关**；M10c 盲写续写（时间线倒流）即实例 |
| 引导层结构化、要素选择可解释、AIMessageEnvelope 一等化 | VS-00D§6 G3/G5/G7 | 「理解层被当废气」（§6 病理）与 G3/G7 同源——文档早已自我诊断，卡在未实现 |

**尖锐的观察**：这个项目的文档体系异常诚实——VS-00D§6、NEM-GAP 表都主动登记了
自己的差距；而病史里一大半缺陷是**已登记差距的实弹版**。所以 A 类的病根不是
「哲学缺文档」，而是**差距登记之后没有回收机制**。项目给小说发明了伏笔账和 R9
超期开火（VS-00F），却没有把同一哲学自反射到工程自身：G1-G7 与 NEM-GAP 就是工程的
伏笔账，从未有超期告警，只能等真实作者踩爆。

### B 类：哲学本身的盲区——文档里没有位置的四件事

1. **作者只有否决权，没有供给权。** 全部成文以「AI 生成 → 候选 → 作者裁决」为唯一
   写入径（00§2、32§6「生成候选可自动」）。「作者亲手提供的内容成为候选」在所有
   文档中**无一字**。哲学把作者建模成裁决者，没建模成供给者——作者主权只有否决
   形态，缺创设形态。（§5 根 1 / R1 的哲学定位）
2. **会话结构内核只覆盖单 turn。** 00§2.1 会话结构定义五条全是本轮之内；**跨 turn
   的作者义务**（诉求被满足前不消失）在内核定义里没有位置。（P2 的哲学定位）
3. **「意图用 AI 判断」只走半程。** 哲学规定判定用 AI 语义（README 原则 4），但
   **对判定的对账**（reason 与 action 自洽）在哲学里没有条目；00§10 十条反模式全是
   工程推进反模式，没有一条运行时语义反模式。（P1 的哲学定位）
4. **决策分权四行诗缺第五行。** 「AI 判断；Agent 取证；Orchestrator 裁决；作者主权」
   ——没有一行负责**结果对账**（产出满足了作者的什么）。作者行使主权的前提是系统把
   可裁决之物端到面前，D8 里连采纳入口都没被指。（P3 的哲学定位）

### 结论

- A 类按既有登记推进即可（G1-G7 / NEM-GAP-06 本就是排期问题），但应先补
  **差距回收机制**：给设计差距表加 VS-00F 式的账本语义（登记即挂账、超期即开火），
  否则登记只是安慰。
- B 类需要**修哲学文档本身**：分权诗补第五行（对账）；作者供给权入 00§2/32；跨 turn
  义务入会话结构内核定义；语义对账入指导原则。P1/P2/P3/R1 是这四条盲区的实现面。
- 修正 §5/§6 的定位：先前把 P/R 当「新原则」提出不准确——P1/P3 属哲学盲区补写，
  A 类差距则根本不需要新原则，需要的是把已写的话当真。
