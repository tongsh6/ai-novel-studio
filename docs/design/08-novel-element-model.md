# 小说要素模型 v3（Novel Element Model）

> 状态：草案 for review（2026-06-13，rev2：接入 VS-00D 小说层与 message layer）
>
> 角色：长篇小说的领域要素全景。`docs/design/domain/21-novel-object-model.md`（对象骨架）、`22-continuity-model.md`（连续性）、`23-style-and-author-intent.md`（风格）的扩展与补全；v3 所有创作类 contract pack 的共同上游（主要消费者：`contracts/VS-00D-ai-guided-authoring-contract-pack.md` 的小说层、`contracts/VS-00C-creative-context-assembly-contract-pack.md` 的创作执行上下文）。
>
> 缘起：创作上下文组装的设计讨论暴露出一个结构性缺口——现有设计把"已经发生的"（连续性对象）和"打算怎么写"（风格对象）建模了，但"**故事被设计成要去哪、当前走到第几步**"这一整个维度只有 `main_outline` 一个文本容器，没有结构化。没有这个维度，任何上下文组装策略都只能让 AI"接着前文写"，而不能让 AI"朝着这本书的方向写"。

---

## 1. 文档定位

本文回答 6 个问题：

1. 一部长篇小说由哪些要素构成（完整清单）
2. 要素如何沿结构尺度链展开（全书 / 卷弧 / 章 / 场）
3. 每个要素的三态（设计态 / 实现态 / 进度态）是什么，为什么必须对账
4. 要素模型与现有对象模型的映射关系与缺口
5. 要素模型有哪几个消费面
6. 缺口按什么原则分期落地

本文不负责：

- 任何对象的字段 schema（落地时由各 contract pack / ADR 冻结）
- prompt 模板与上下文预算（`VS-00C`）
- AI message envelope、call site 渲染与缺失处理（`VS-00D`）
- 提炼算法、召回排序、embedding 实现

本文只冻结要素模型的骨架。

---

## 2. 为什么需要要素模型

### 2.1 四个消费面共用同一地基

以下四件事如果各自发明"小说有什么"，会产生四套互相错位的领域语言：

1. **规划动作的输出 schema**——AI 产大纲/章计划时该按什么结构产出
2. **maintenance 的提炼目标**——正文采纳后该从中提炼什么
3. **结构面板 / 作品档案的展示维度**——作者看到的"这本书的账"有哪些
4. **上下文组装**——写某一段时该给 AI 带什么

要素模型是这四个消费面的单一上游。任何一面需要新维度时，先回到本文，而不是在消费面就地发明。

### 2.2 要素模型与模型能力无关

两个论证：

1. **窗口大小不消解要素模型。** 即使上下文窗口能容纳全书正文，dump 全文仍然错误——成本、延迟、关键信息被淹没（`domain/26-context-assembly-policy.md` §2 的理由本就与窗口大小无关）。窗口变大只移动"能带多少原文"的裁切线，不改变"该带什么"。
2. **设计态与进度态不在正文里。** 主题、人物弧光设计、承诺兑现状态、节奏定位——这些存在于作者的蓝图和账本中，不存在于已写出的文本中。无限上下文最多让"实现态"全量可见，永远推导不出"故事要去哪"。

因此要素模型是模型无关的领域问题。开发阶段使用本地小模型（地板档）是刻意选择的 forcing function：最严苛预算逼出诚实的分层与压缩；按最弱模型裁剪要素模型、或因当前模型能力 defer 某要素的建模位置，都是设计错误。

## 3. 模型结构：要素 × 层级 × 三态

完整模型是立体的，不是平面清单：

```text
要素（§4 的 37 项）
  × 结构层级（全书 / 卷弧 / 章 / 场 —— 同一要素在不同层级是不同的东西）
  × 三态（设计态 / 实现态 / 进度态 —— §5）
```

例：「冲突」在全书级是核心冲突与赌注升级路径，在卷级是本卷要解决的对抗，在章级是本章推进哪条线，在场级是这一场谁和谁要什么；它同时有设计（大纲里怎么规划的）、实现（正文里实际写成了什么）、进度（推进到哪一步）三态。

## 4. 要素全集

### 4.1 全书级 —— 这是一本什么书

| # | 要素 | 内容 |
|---|---|---|

| E02 | 主题 | 核心命题、价值冲突——这本书在"说什么" |

| E12 | 命名体系 | 人名/地名/功法名/章节名的风格一致性 |

| E27 | 对白设计 | 人物声音区分、潜台词、对白/叙述/动作配比 |
| E28 | 动作编排 | 打斗与动作的空间逻辑和因果 |
| E29 | 内心戏 | 情绪流动深度、思想呈现方式 |
| E30 | 场间过渡 | 时间跳跃、视角切换的衔接 |

| # | 账本 | 记什么 |
|---|---|---|
| E31 | 连续性账 | 状态、时间线、规则一致性 |
| E32 | 伏笔账 | 埋了哪些、养到什么程度、何时回收 |
| E33 | 弧光账 | 每个人物走到变化设计的第几步 |
| E34 | 冲突账 | 主线 / 各支线推进度 |
| E35 | 信息账 | 读者已知 / 各角色已知 / 真相全貌——悬念与反转的地基 |

## 5. 三态与对账

### 5.1 三态定义

几乎每个要素同时存在三个状态：

| 态 | 含义 | 典型载体 |
|---|---|---|
| 设计态 | 写之前的蓝图 | 大纲、人设、章计划、卷蓝图 |
| 实现态 | 已写出的正文里实际呈现的样子 | 已采纳正文及其提炼物 |
| 进度态 | 设计兑现到了哪一步 | 各类账本（E31-E37） |

### 5.2 实现态必然偏离设计态

写着写着配角戏份变重、人物性格在对白里漂移、计划中的伏笔写出来太显眼——这是创作常态而非事故。因此系统必须能：

1. 从已采纳正文**提炼实现态**（`design/25` maintenance hooks 的深层意义）；
2. 与设计态**对账**，暴露偏离；
3. 把裁决权交给作者：改设计迁就正文，还是改正文回归设计。

对账产物属于 tentative 层，经 adoption 进入权威层（沿用 `22` §14 与 ADR-0010 边界），不得静默改写设计态或实现态任何一方。

### 5.3 缺一态的系统形态（反模式）

- 只有设计态、不提炼实现态：30 章后"大纲说一套、正文写一套、AI 按大纲继续写"。
- 只有实现态、没有设计态：纯前文续写，无主题无方向的随波逐流。
- 两态都有、不对账：偏离静默累积，崩溃只是延迟到来。

## 7. 四个消费面的使用规则

| 消费面 | 使用方式 | 反模式 |
|---|---|---|
| 规划输出 schema | AI 产章计划/卷蓝图时按对应层级要素结构化产出（章=E18-E22） | 让 AI 产一段自由文本摘要再事后猜结构 |
| maintenance 提炼 | 正文采纳后按要素维度提炼实现态（情节/人物/伏笔/情绪），更新相关账本 | 只提炼一段含糊的"本章讲了……" |
| 结构面板 / 档案 | 作者看到的就是各要素的进度态账本 | 面板各自发明展示维度 |
| 上下文组装 | 上下文 = 要素模型在当前写作坐标（卷 V，章 N，场 M）上的投影：坐标定了，每个要素取全书级摘要、本卷条目还是本章明细可机械推导 | 按"塞得下多少"而不是"坐标需要什么"组装 |

写作坐标（WritingCoordinate）是要素模型进入 AI 调用前的必经选择器，不是 prompt 文案里的自然语言提示。坐标至少回答：当前生命周期阶段、写作模式、目标单位、目标卷/章/场、来源 turn。只有坐标先确定，系统才能判断哪些设计态、实现态、进度态材料必须进入上下文，哪些材料可以按预算降级，哪些缺失必须阻断或请求作者确认。窗口大小只能影响原文 excerpt 的裁切线，不能改变坐标本身。

### 7.1 作为 VS-00D 小说层的使用规则

`VS-00D` 的 Novel Creation Contract / `NovelLayerMessage` 从本文选择和展开小说要素，但不能把本文变成每轮 prompt dump。进入 AI message 前必须先完成三步：

1. **确定写作坐标**：全书、卷、章、场、段落对应的要素粒度不同。
2. **选择本轮要素焦点**：Planner 可以让 AI 参与判断本轮关注人物动机、章节功能、信息释放、伏笔、连续性、文风或质量门；系统必须记录选择理由。
3. **区分判断框架与作品事实**：本文提供“应该检查什么”的框架；当前作品是否已有这些材料，必须由 `DialogueContext` / WorkStateMessage 给出。

最小输出到 AI message 的形式不是 37 项全量清单，而是：

```text
NovelLayerMessage
  always_on_principles
  expanded_elements
  quality_gates
  selection_rationale
  omitted_elements
```

反模式：

- 每轮把本文整段复制给模型。
- 让 AI 从作者自然语言里自行决定当前作品已有哪个要素状态。
- 把某个要素缺失解释为“作品事实不存在”，而没有回到当前作品层查证。

## 8. 分期原则与落地归属

分期依据是**数据依赖与杠杆率**，与当前接入模型的能力无关：

| 顺序 | 落地项 | 关闭缺口 | 杠杆 / 依赖 |
|---|---|---|---|
| 1 | 章级设计结构化（章计划按 E18-E22 产出并物化） | NEM-GAP-03 | 杠杆最高：规划产物结构化后，写章上下文自动有方向；复用既有规划链路 |
| 2 | chapter_summary 按要素分维度（情节/人物/伏笔/情绪四栏） | NEM-GAP-05 的近似 | 一个对象同时喂四本账的最小近似；归属 `VS-00C` CP2 |
| 3 | 场级 craft 最小槽（场景目标/出场人物议程/情绪） | NEM-GAP-04 子集 | 接续既有"创作槽位"方向（目标字数槽同型） |
| 4 | 主题/定位补字段 | NEM-GAP-01 | 最便宜：work 元信息或 worldbuilding 增字段，进入常驻上下文 |
| 5 | 五本账对象化 + 三态对账机制 | NEM-GAP-05 / 06 | 独立 contract pack；依赖前几步的提炼数据基础；本产品区别于"通用聊天续写"的护城河 |
| 6 | 卷级蓝图、设定引擎/成长体系/命名对象化 | NEM-GAP-02 / 07 | 随对应创作动作（开新卷、立体系）的 slice 提出时再冻结 |

**探索面同步律（2026-07-19，CP5 落地经验；2026-07-21 升格为开工检查第七问
Exploration，见 `docs/engineering/vertical-slice.md` §5）**：任何要素物化的
slice，必须回答"探索面（判断循环内部翼工具目录）如何可达"。先例教训：chapter_summary
压缩层建成后探索翼漏接，直到 CP5b 才补面——要素落地与探索可达必须同批收口，
否则账本建了 AI 查不到，等于没建。

## 9. 本文冻结的硬骨

1. 小说要素模型 = 要素（37 项）× 结构层级（全书/卷弧/章/场）× 三态（设计/实现/进度），不是平面清单
2. "向前看"的维度（主题、弧光、冲突进度、信息账、承诺账）必须有建模位置；不能以 main_outline 文本容器替代
