# AU-15：模型自主求证与证据闭环（设计登记）

> 状态：**Proposed / 未实现、未注册 quality 运行场景**。
> 上游：`../../00-vision-and-engineering-roadmap.md` §2.4、`../../contracts/VS-00K-evidence-seeking-authoring-contract-pack.md`、`../../adr/ADR-0030-evidence-seeking-authoring-v3.md`。
> 执行任务：`tasks/slices/B39-evidence-seeking-authoring.md`。
> 本文只登记候选验收场景，不声明任何场景已经通过。

## 1. 作者价值

作者只负责自然创作，不应反复提醒 AI“前面已经写过”。当固定上下文没有完整答案时，AI 应能自己发现信息缺口、读取真实作品材料、说明依据，再继续规划、写作或修订；查不到或证据冲突时，应诚实停下，而不是编造。

本家族验证的是**通用求证能力**，不是时间线专用功能。首个实施锚点优先使用未进入任何专用 packet 的人物承诺/关系细节；时间连续性只是另一个可精确核对的场景。

## 2. 统一验收口径

每个场景必须区分两类证据：

1. **机制证据**：计划步、工具观察、来源 refs、预算、恢复、候选与采纳边界，可由确定性 provider 和局部测试证明。
2. **模型行为证据**：真实模型在没有领域专用 prompt 分支的情况下，自行决定查询、使用观察或承认缺口。确定性替身预先排好探索步骤不能替代这一类证据。

共同硬边界：

- 外部自动化只通过真实 WorkspaceChat / Tauri 用户入口操作；产品代码不读取验收开关、slice id 或专用 query。
- 首轮固定上下文是否含答案不作为通过标准；必须核对模型选择的探索、真实观察及后续 provider 请求。
- 工具观察必须来自真实作品数据；不得由产品代码按场景硬编码答案。
- 探索默认只读；未经作者采纳不得新增 canon。
- 不要求每个新句子都有旧来源，但模型声称使用的既有事实 ref 不得伪造；未返回 used_context_refs 时记 unknown，不从 supplied refs 推导。
- Base 已足够时不强制探索，不能把“每个 run 都调用工具”误写成目标。
- 真实模型语义表现、确定性机制与文学质量分别报告，不互相代签。

**实模判据先于执行冻结**：自然输入、模型/参数、预算、重复次数、禁答集和通过线必须在 CP 开工前登记。关键缺事实场景至少独立运行 2 次且全部满足规定的证据链，timeout / 格式失败计入分母；至少保留一种未参与调词的措辞。实模 PASS 与 stub PASS 分开报告，失败只记未闭环。

## 4. SC-AU15-A0：Base 已足够时不强制探索

提供一个小而完整的 Base，使当前任务无需旧作品事实。模型可以直接准备并生成候选，不得为了证明“agentic”而强制先查工具。断言无探索步时仍能区分 ready 与 missing，不将“零工具调用”误判为未求证或失败。

## 5. SC-AU15-A1：未预装的人物承诺/关系细节由模型自行取得

### 前置

- 通过真实创作与采纳，在较早章节写入一条人物承诺或关系事实，例如“沈砚答应三天后回灯楼接顾青”。
- 该事实不进入任何专用 packet；后续固定摘要或 Base 不含完整内容，但真实正文可通过通用 `chapter_read / prose_search` 读取。
- 作者后续输入只提出自然创作目标，不说“请先调用某工具”。

### 操作与证据

1. 外部 driver 在真实工作台请求后续章节创作。
2. 从真实 AgentPlan / plan revision 证明模型选择了只读探索，而不是 APP 按领域关键字自动加步。
3. 观察包含真实承诺/关系表达、章节 refs、来源版本与覆盖。
4. 后续 writer 的真实 provider 请求包含上述观察或其保真投影。
5. 生成候选与该承诺/关系相容；作者看到探索活动、候选与来源，采纳前没有新 canon。
6. `used_context_refs` 若返回，必须包含真实已见来源且不得越界；未返回记 unknown，不伪报“未使用”。

### 反证

- 只让 stub 按脚本排探索步，不算真实模型自主求证。
- 模型没有读取来源却声称“已核对前文”，应记录失败，不能用正文碰巧正确抵消。
- 只断言 APP 的固定 prompt 含答案，不算本场景通过。

## 6. SC-AU15-A2：另一未定制要素复用同一求证链

选择另一类未配置专用 packet 的事实进行对照。优先采用可精确核对的时间关系：前两章分别写“过了三天”和“又过了两星期”，后续结果应与累计十七天相容。

要求：

- 与 A1 使用相同产品构建和契约，不修改 CarryRegistry、prompt 分支或工具白名单来特批时间。
- 模型使用同一探索目录和准备流程取得真实来源，后续请求包含观察。
- 对比 A1 的产品 diff，不得出现为该场景新增的语义分支；累计计算或读模型的归属另行审查，不能由硬编码答案冒充。

A1 + A2 共同证明“通用求证”，而不是“人物补丁＋时间线补丁”。后续还可用物品归属等未定制要素复用同一矩阵，不为每个要素新增独立架构。

## 7. SC-AU15-B1：未知与冲突不得被填平

分别覆盖：正文没有所需事实、多个参照存在歧义、当前来源冲突、来源失效或版本不匹配。

模型可以继续查询、明确假设、请求作者或按契约降级，但不得把未知渲染成已确认事实。系统须保留查询、空结果／歧义／冲突分类、来源与最终处置。若进入作者等待，必须复用既有决策面，不新增隐藏状态。

## 8. SC-AU15-B2：有界求证与恢复

- 相同 tool + query 的重复调用按既有 no-progress 规则处理；合法续读页不误判为重复。
- 达到 run 预算后停止新增探索，说明已完成与缺失部分，不无限循环，也不伪装 goal_satisfied。
- 取消后无迟到写入。
- backend / 页面恢复后，已执行观察、来源版本和计划位置可重建；不得因旧 prompt 残留把 stale 观察当成当前事实。
- replay 默认不重调模型。

## 9. SC-AU15-C1：越界证据引用

外部替身返回包含未读取 ref 的 `self_report.used_context_refs`。机械校验必须发现该 ref 不在 Base 公开 refs 与实际观察 refs 的并集内。

预期：

- 记录 unbound ref、对应 provider call 和 run；
- 不修改 artifact title/body/rationale 字节；
- 不把该 ref 当成已核实依据；
- 按契约进入 warning、补充求证或作者裁决；
- 新创作内容没有旧 ref 本身不被误判为违规；未返回自报告记 unknown。

## 10. SC-AU15-C2：写后仍需补充求证

模型生成候选后，self_report 或质量评估发现既有事实缺口。run 不直接静默完成或采纳，而是在既有预算内选择补充探索、修订或等待作者。必须证明补充观察来自真实读取，修订候选仍是 tentative，原字节因果链不被服务端修补。

## 11. SC-AU15-D1：携带退役必须凭证据

只有在真实 run 能证明某固定携带块长期重复、未使用或可由观察／派生替代时，才提出迁移。逐项记录保留为 Base、转为按需或改为 Derived 的理由与回归证据；不得因元原则一次性清空现有携带。

## 12. 证据产物与命令方向

实现时由 B39 将场景注册进 `quality/acceptance/scenarios/`，统一真实请求证据词表与 request/response/ref 顺序，长期沉淀可复跑命令。至少输出：

- 真实页面截图与作者可见活动；
- AgentPlan / plan revision / observations / no-progress / recovery 记录；
- 实际 provider 请求与响应引用；
- Base refs、观察 refs、used_context_refs 的集合对账；
- 候选、采纳与 production write 证据；
- 真实模型与确定性 provider 的分层结果；
- 实模输入、参数、重复次数、失败分母和未参与调词的保留措辞。

未注册、未运行、缺实模凭据或仅有局部测试时，相关场景保持 blocked / 未闭环，不能用历史探索场景或仅有请求成功代替。
