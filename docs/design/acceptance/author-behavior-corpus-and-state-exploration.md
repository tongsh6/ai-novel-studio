# 作者行为语料生成与状态探索验证设计

> 状态：B70 当前实施设计基线（2026-10-30）。作者已确认方向；CP0 冻结资产已存在，CP1–CP3 仍按任务证据验收，设计接受不代表实现或场景 PASS。
>
> 执行状态唯一来源：[B70](../../../tasks/slices/B70-author-behavior-corpus-and-state-exploration.md)。
>
> 运行资产唯一来源：[quality/acceptance/author-behavior/](../../../quality/acceptance/author-behavior/README.md)。本文解释设计语义与实施边界，不复制一份平行语料或判卷表。

## 1. 背景与要解决的问题

现有外部 UI 验收能够证明“一个固定输入和固定操作序列穿过真实主链，并得到预期结果”，但主要不足是：

- 输入多来自既有日志或为 slice 写定的少量句子，表达空间窄。
- 操作顺序预先写死，难以发现跨轮、跨状态和非固定顺序问题。
- 场景数量不能说明覆盖了哪些作者目标、状态、路径和风险。
- 持续依靠独立开发者人工创作、整理语料和编写剧本，无法与实现进度同步。

I1/I2/I3 继续证明内容来源、输入差异与 nonce 贯通，但不扩大解释为语义理解或作者行为覆盖证明。

本设计的目标是：**以少量人工目标定义为种子，离线生成并冻结语料，通过真实 UI 做数据驱动回放和状态驱动探索，自动检查硬事实、报告真实覆盖，并把新失败转为永久回归。**

## 2. 已确认的架构选择

采用“**仓内管理、运行时外挂、证据内生、判卷外部**”：

- 语料、格式、生成器、执行器和判卷规则与产品同仓库、同版本演进。
- 生成、探索与判卷均在产品运行时之外，不进入生产启动路径。
- 观测优先使用真实页面、WebSocket、业务日志、Provider 请求、trace、receipt 和只读持久化快照。
- 不建设独立仓库或另一套任务、verdict、证据体系。
- 不为验收在 `apps/*/lib` 或 `frontend/src` 增加开关、slice 识别、自动操作、专用 DOM hook、Channel/API 事件或生产 provider 注册。

“内置进开发与质量流程”是目标；“内置进生产 App 自我验收”不是目标。

## 3. 范围与结果分层

### 3.1 三类结果必须分开

| 结果层 | 证明对象 | 允许证据 | 不得冒充 |
|---|---|---|---|
| 机制证据 | 页面动作、请求、状态推进、对象、权限、采纳、持久化与恢复 | 确定性 provider、外部 UI、WS/日志/DB/receipt | 真实模型语义或文学质量 |
| 模型行为证据 | 真实模型在自然输入下是否理解、求证、使用观察和承认未知 | 预注册真实 provider 请求/响应、独立重复、保留措辞与 B42 证据链 | 由 HTTP 200 或 stub 代签 |
| 文学质量 | 正文、规划和修订是否具有良好的叙事质量 | 独立评价与人工盲评 | 并入机制 PASS 抵消硬违规 |

### 3.2 本设计覆盖

- 作者目标模板、合成状态、冻结案例、oracle 和覆盖报告。
- 离线语料生成、去重、冻结、选择和版本管理。
- 数据驱动真实 UI 回放。
- 状态驱动随机探索、种子复现、失败保存与缩化。
- PR/nightly/explore/real-llm 执行分层及 B41/B42 证据接入。

### 3.3 明确不覆盖

- 不重写 B27 的 20 例与 40 episode 门槛，不重做 B34 历史日志抽取。
- 不重建 B41 verdict、B42 evidence chain/release layer 或 B37 等待监督。
- 不一次性迁移所有既有固定场景；它们继续作为机制回归。
- 不用模型生成器自行定义并签署自己的正确性。
- 不声称合成语料代表广泛真实用户；阶段性真实创作用于发现新目标，不是日常语料生产义务。

## 4. 总体数据流

```text
人工目标模板 + 合成状态 + 全局不变量
                ↓
       离线生成 / 派生 / 去重 / 过滤
                ↓
       冻结案例（含 provenance/split/oracle）
                ↓
       ┌────────┴────────┐
       │                 │
数据驱动回放          状态驱动探索
固定输入/状态         根据页面状态选择动作
       │                 │
       └────────┬────────┘
                ↓
真实 WorkspaceChat / Tauri → socket/API → application → persistence
                ↓
页面 / WS / app log / provider 请求 / receipt / 只读 DB 快照
                ↓
硬不变量 + 终局允许集 + 路径/证据要求 + 覆盖统计
                ↓
B41 verdict / B42 evidence / artifacts / 失败转回归
```

产品只接受真实用户动作。外部 harness 可以准备隔离测试数据、启动服务、操作 UI 和读取证据，但不能直接 push Channel payload 来代替作者操作，或直接调用业务模块制造验收结果。

## 6. 作者目标、状态与案例语义

### 6.1 目标模板

目标模板描述作者想得到的语义后果，不描述固定 UI 步骤。每个目标至少包含：

- 作者目标与来源。
- 可接受的终局动作与候选/采纳效果。
- 禁止行为。
- 会改变正确结果的状态维度。
- 必须实际构造的负例陷阱。
- 自然表达扩展指引，而非关键词路由规则。

当前首批目标为 F1 进度查询、F2 章正文写/重写、F3 设定/伏笔讨论与保存边界。它们用于证明体系可运行，不构成完整作者意图目录；后续按 B34 高频缺口和新失败扩展。

### 6.2 状态

状态不只是 seed 函数名，而是会改变正确行为的可观察事实组合，例如：

- 是否有章节、计划、已采纳正文和 pending 候选。
- 目标是否唯一、同名、失效、stale 或跨作品。
- 作品事实是否为空、未知或读取失败。
- 当前是否存在活跃运行、确认或历史会话。

`states.yml` 当前 S1/S2/S3 是最小起点。新增状态必须说明它改变了哪条期望，不能只为了数量增加近似夹具。

默认只用合成样书。真实作品或真实日志须明确授权、脱敏并保留来源边界；离线生成模型默认不得读取这些材料。

### 6.3 冻结案例

一个案例必须绑定：

```text
目标 + 状态 + 自然表达 + provenance/split
+ 允许的终局/效果 + 禁止行为 + oracle 引用 + 执行 tier
```

`expression_frozen: true` 表示运行前不得为追求通过而改写输入。修复产品后使用同一输入复验；若确需修改案例本身，必须新建版本/案例并保留旧资产与原因。

### 6.4 动作白名单与完整轨迹不是一回事

当前 `cases[].expected.allowed_actions` 是**终局动作白名单**，不是有序调用序列：

- 先 `explore` 后 `reply` 的终局可以记为 `reply`，但必须另有探索与证据链断言。
- 先 `explore` 后 `execute` 的终局可以记为 `execute`，但不能因此省略“观察进入后续真实请求”的检查。
- `oracles.target_oracles.allowed_result_sets` 描述合法路径形态；CP1 当前确定性评估器只消费 case 的终局白名单与效果集合，不能把完整路径形态写成已机器验证。
- CP2 才引入有序轨迹/状态转移匹配；在此之前，路径覆盖只能标为声明或局部证据。

## 7. 语料获取、生成与分组

### 7.1 低成本来源顺序

1. 人工维护少量目标和正确性规则。
2. 复用 B27/B34 的语义思想、历史缺口和公开可追溯案例来源。
3. 离线 LLM 按目标与状态扩增表达，生成一次、冻结后长期复用。
4. 程序变异对象数量、状态、指代、操作顺序、故障和重复动作。
5. 自动探索的新失败经去重、缩化和修复后转回归。
6. 阶段性真实创作只用于发现新目标和偏差，不与每次实现提交绑定。

### 7.2 Provenance

- `human_template`：人工写定的目标表达或改写。
- `derived_frozen`：从历史日志、既有案例或 fixture 派生，必须有 `source_refs`。
- `generated_frozen`：离线生成后冻结，必须有生成器标识、生成时间、源模板和冻结标记。

`generator` 必须能定位到可复跑的生成配置，包括模型/参数、提示或配置版本及输入模板 hash；如当前单字段不足，应通过 additive 生成 manifest 补全，不把不可追溯的模型输出直接入库。

### 7.3 Split

- `dev`：可用于开发定位和规则调整。
- `regression`：已发生失败或高风险固定回归，不得测后调词。
- `holdout`：未参与调词的保留表达，用于独立评估。
- `explore`：随机探索池，不计入固定回放通过率。

同一 holdout 表达不得与 dev/regression 共享 normalized text。这个校验只是最低防泄漏要求，**不能证明语义近义独立**；生成与评审时还应按源模板、近义聚类和生成批次检查泄漏。

失败转回归必须新增 case id，保留原失败案例、split、证据和失败分母，不得原地改 split 或删除失败来“洗绿”。

## 8. 外部观察契约

oracle 消费的是外部 driver 从原始证据派生的观察，不是产品为了验收自报的布尔值。

当前最小观察包括终局 action、effects、canon delta、author action、adoption receipts、完成声明、对象一致性、重复副作用、supplied 状态和 unknown 原因。其实语必须统一：

- `canon_write_delta` 只计算权威作品事实变化；TENTATIVE 候选不是 canon 写入。
- `author_action` 只表示真实作者经产品 UI 发起的授权/采纳动作，不能把普通发送或 fixture 行为算作授权。
- `adoption_receipts` 只计算真实采纳回执，不计算候选生成或普通工具成功。
- `object_mismatch` 必须由真实目标 ref 与实际操作 ref 比较得出，不能由产品自报。
- `duplicate_side_effect` 应由候选、登记、receipt 或唯一键前后差异计算。
- `claims_completion` 无法可靠从可见文本判定时必须 unknown，不得默认 false。
- `supplied_status` 在真实运行中必须显式记录；缺失或无法核对同次请求字节时为 unknown，不得按 known 放行。
- 原始证据引用随每例保存，使观察可重算；派生观察与原始证据矛盾时以原始证据重算并记证据错误。

确定性 fixture 只是刺激源，不是正确性裁判。fixture 的输入→输出映射与 oracle 必须独立，不能用同一份“预期正确答案”同时生成产品响应并判卷。

## 9. 判卷语义

### 9.1 判定顺序

每个 case 按以下顺序判定：

1. **证据是否足以判定**：缺观察、缺 action、缺必要来源或请求证据 → `unknown`。
2. **是否命中硬违规**：错误对象、未授权 canon 写、重复副作用、虚假完成、来源字节替换等 → `fail`。
3. **终局/效果是否在允许集合**：不属于允许结果按当前契约判 fail 或语义 unknown；不得为了宽松而一律 unknown。
4. **必要路径与证据是否满足**：需要探索、真实读取或采纳绑定的案例，缺路径证据不能 PASS。
5. 全部满足才可 `pass`。

硬违规优先于平均分和其他良好表现；文学质量不进入该判定。

### 9.2 `unknown` 不是宽松通过

- 证据缺失、读取失败、无法判定来源、模型没有可判终局 → unknown。
- 已明确观察到产品选择了禁止终局 → fail，不得改称 unknown。
- 未触发任何允许路径但也没有硬违规时，可按目标 semantic policy 记 unknown，交由对应语义流程复核。
- 真实 provider 缺凭据/模型/平台只能 blocked/skipped/evidence_missing，不能 PASS。

### 9.3 负例与变异证明

声明一个负例陷阱不等于覆盖它。负例闭环必须证明：

1. 初始状态确实制造了目标歧义、越权机会或故障条件。
2. 输入/动作实际到达该条件。
3. oracle 能抓住错误对象、未授权写、重复副作用或虚假完成。
4. 合法路径不会被同一规则误杀。

仅有单元测试中的合成 observation 可以证明 oracle 接线，不能证明真实页面能到达负例；只有真实页面负例与变异测试各自证据分开记录。

## 10. 状态驱动探索

### 10.1 行动模型

探索器根据当前真实页面和外部观察选择动作，不执行预写完整剧本。动作可包括：

- 发送、补充、纠正、反悔和改变话题。
- 编辑、拒绝、确认、重复确认、采纳与取消。
- 切作品、查看历史、重开、断线/恢复和阅读往返。
- 对同名、stale、历史或跨作品对象执行合法/故意非法操作。

动作选择可随机，但必须记录种子、动作集合、选择理由类型和完整轨迹。产品仍只接受真实用户可见操作。

### 10.2 每步不变量

每个动作后均检查 G1–G6 及适用的现有 I1/I2/I3、作品隔离、版本/freshness 和作者采纳边界，而不是只在长跑结尾检查。

等待预算、心跳、fail-fast、termination 与进程清理由 B37/现有 native harness 复用，不新建平行监督循环。

### 10.3 探索结果语义

- 探索完成且没有硬违规，只能说明本次种子与行动轨迹的机制结果。
- 随机探索不自动证明语义质量，也不把未触发的目标算作覆盖。
- 产品失败、driver 失败、等待超时和证据缺失分别计数；不得删除失败分母。
- 失败批次只读保留，重跑使用新 artifact，不覆盖旧证据。

### 10.4 失败缩化

缩化必须保持同一违规类别和核心证据，不得把“一个较短但不同的失败”冒充原失败最小复现。输出：

- 原种子与完整轨迹。
- 缩化后的最小动作序列。
- 被保留的违规与证据引用。
- 重放命令和隔离数据版本。
- 去重指纹及关联历史失败。

修复后先按原轨迹/种子复验，再把最小案例登记为 regression。

## 11. 覆盖报告

覆盖报告必须区分三类事实：

| 类别 | 含义 | 示例 |
|---|---|---|
| 静态声明覆盖 | 语料中声明了哪些目标、状态、oracle 和负例 | case 引用 HO2 |
| 实际执行覆盖 | 本次运行真实到达了哪些目标、状态、路径和陷阱 | 实际构造两个同名章并发出修订 |
| 判卷有效覆盖 | 哪次触发有足够证据且 oracle 实际作出判定 | 错绑发生并被抓，或合法消歧通过 |

`negative_traps_covered` 与 `oracles_covered` 不得只从声明列表复制后冒充实际执行覆盖。若 v1 字段暂用于静态引用，报告必须显式标为 declared，并另列 executed/evaluated；缺执行数据时记 unknown 或 gap，不写“已覆盖”。

至少报告：

- 目标 × 状态 × split 的案例数与执行结果。
- 必要状态维度和同句异境组合缺口。
- 负例声明、实际触发、违规检测和合法路径反误杀情况。
- 状态/动作/转移覆盖（CP2 起）。
- pass/fail/unknown/blocked 和 driver/timeout 失败分母。
- corpus sha、git HEAD、surface、driver、provider/model 与证据引用。
- 真实模型语义未覆盖等固定开放缺口，不能被确定性 PASS 隐藏。

## 12. 执行分层与成本纪律

| 层 | 内容 | 通过语义 |
|---|---|---|
| PR/提交前 | 格式校验、少量代表 case、受改动影响目标族 | 快速机制回归，不外推完整覆盖 |
| nightly | 冻结语料回放、硬 oracle、代表负例和状态矩阵 | 当前 HEAD 的确定性场景证据 |
| explore | 多种子状态探索、长会话、恢复和失败缩化 | 发现新问题；不因部分种子通过隐藏其他失败 |
| real-llm | 预注册 holdout 与语义子集、独立重复和 B42 证据 | 模型行为独立结论，不由 B70/stub 代签 |

生成模型不参与每次测试；日常回放只读冻结资产。真实模型只跑需要模型判断的子集，通常在里程碑、发布前或独立资源窗口执行。

CP1 新场景先取得稳定、可诊断证据，再决定是否进入 blocking PR gate。不得为了减少波动而缩小断言、删除失败种子或跳过 manifest。

## 13. 与现有能力的复用边界

| 现有资产 | 复用 | 不复用/不重复建设 |
|---|---|---|
| B27 语义案例 | 保留集、同句异境、零容忍、自然输入和事实判卷思想 | 不复制 20 例、不重跑其专属门槛 |
| B34 日志与覆盖矩阵 | 作者目标来源、高频缺口、unknown 不猜和只读抽取器 | 不重新做一套日志解析或历史复验 |

## 14. 安全、隐私与数据边界

- 默认使用合成样书和隔离测试 DB，不读取或修改作者 dev/stage 数据。
- 真实日志和作品只在明确授权后使用，脱敏保留语义，不公开原始作品。
- 离线生成器默认不接触真实作品、凭据或 secret 文件。
- 外部 DB 检查只读；写操作只能经真实产品用户链或隔离 fixture setup。
- 任何故障注入、provider 替身和 seed 只存在于 test/support/外部 harness，不进入生产 runtime。
- 真实模型运行遵守既有单槽、预算、模型生命周期与 unload 证据要求。

## 15. 实施 checkpoint 的验收要求

### CP0：格式与资产冻结

已完成的事实：五类格式、3 个目标族、3 个状态、9 条冻结案例、G1–G6/HO1–HO6、校验器和静态覆盖示例已建立。它证明格式和最小资产存在，不证明真实页面或运行覆盖。

### CP1：最小数据驱动真实页面闭环

必须同时具备：

- 至少 3 个目标族的多表达、多状态回放，包含同句异境或歧义负例。
- 外部 driver 经真实 `WorkspaceChat` 输入和操作，穿过后端与持久化。
- 状态 seed、确定性 provider、场景 manifest 和 verdict 全部接通。
- oracle 正反例证明能抓错对象、越权写、重复副作用和虚假完成。
- 覆盖报告来自真实运行，区分声明、执行与判卷有效覆盖。
- 缺观察/缺 supplied/缺必要证据均不得 PASS。
- 真实模型语义仍未运行时明确保留缺口，不阻塞确定性 CP1，但不得代签。

### CP2：状态探索与失败缩化

必须至少一个非固定操作顺序场景由外部真实页面完成，并具有种子复现、每步不变量、状态/转移覆盖、失败保存、缩化和修复后回归。

### CP3：覆盖扩展与分层

必须完成受影响 PR 子集、后台/夜间探索、失败转回归、覆盖扩展和真实模型语义子集入口。真实模型结论仍按 B42 预注册与证据完整性独立判定；CP3 不因接入入口就宣称模型语义 PASS。

完整范围仍由 B70 原任务维护，任一 CP 完成不得替代其他计划内后果。

## 16. 当前实现交接时必须复核的差距

以下是设计复核发现的实现边界，不是新的产品需求：

1. **真实观察缺省必须为 unknown。** 当前评估库对缺省 `supplied_status` 的合成输入较宽松；真实 driver 不得依赖该缺省，CP1 收口前应通过观察 schema 或评估器修正保证缺失不放行。
2. **覆盖报告不能复制声明当执行。** 当前 `negative_traps_covered`/`oracles_covered` 主要来源于声明引用；CP1 必须补 declared/executed/evaluated 区分或等效显式语义。
3. **负例状态必须真实存在。** 例如同名章错绑陷阱需要实际同名/多目标状态，不能只凭目标模板里的 trap id 记覆盖。
4. **HO6 与未引用 oracle 需要处置。** 没有案例触发的 oracle 应进入 gap 或明确 scoped not_applicable，不能在示例中空 gaps 后被读成完整覆盖。
5. **完整路径尚未由当前评估器证明。** 终局 action 通过不等于 explore→reply/execute 的观察链已验证；涉及求证的案例必须消费 B42 证据，不能只看终局。
6. **example 不是运行报告。** `coverage-report.example.json` 只证明格式，不能作为场景执行、真实覆盖或 PASS 证据。

这些差距由实现者在对应 CP 内闭环，不需要为它们另建平行任务或修改生产产品语义。

## 17. 完成后的诚实边界

即使 B70 全部落地，也只能说明：

- 作者目标、表达、状态和操作覆盖显著扩大。
- 固定回归与随机探索共享真实产品链和可信证据。
- 硬违规、未知和未覆盖能够稳定区分。

仍不能单独证明广泛真实作者代表性、所有模型语义可靠或文学质量达标。真实使用反馈、真实模型行为评估和 I10 人工盲评继续保留各自独立入口。
