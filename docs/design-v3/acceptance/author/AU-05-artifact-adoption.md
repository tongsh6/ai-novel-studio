# AU-05 采纳创作产物

> 作者视角：AI 生成的所有内容（如主角设定、剧情大纲、章节片段）默认都是"草稿"或"候选方案"。它们会以卡片的形式展示给我，让我挑选。只有当我明确点击"采用"或"加入作品"后，这些内容才会真正变成我小说的正式组成部分。

---

## 1. 我能做什么

| 我能做什么 | 系统怎么回应 |
|-----------|------------|
| 让 AI "帮我想三个可能的主角名字" | AI 给出三张候选卡片，每张有名字和简单的背景 |
| 浏览并对比不同的方案 | 候选方案作为讨论材料展示，不改变作品正文 |
| 选中其中一个方案 | 系统记录我的偏好，并提示是否"确认采用" |
| 点击"采用"按钮 | 系统正式将该方案写入作品设定，并刷新我的作品视图 |
| 对所有方案都不满意 | 我可以不理会这些卡片，或者让 AI "换一批" |

明确不能做的：
- AI 不应该自动把生成的草稿写入我的正式章节或设定集。
- 我不应该在没有"采用"的情况下看到这些内容出现在作品导出或阅读视图中。

## 2. 验收场景

### 场景组 A：草稿生成 (Tentative Generation)

#### A1 — 生成内容默认为草稿

**作为作者**，我要求 AI "设计一个反派组织"。
**系统应该**生成几个候选方案，并明确标注它们为"草案"或"候选"。

```
作者: 设计一个反派组织。
AI: 我为你构思了三个各具特色的反派组织方案：
    [方案1: 影之议会] - 潜伏在暗处的古老势力...
    [方案2: 灵源重工] - 垄断了全球灵气的巨头...
    [方案3: 虚空教派] - 崇拜异位面神明的狂信徒...
    (这些内容尚未加入你的作品设定)
```

**验证点**：
- [ ] 我收到了包含 `tentative_artifacts` 或 `candidate_directions` 的回复
- [ ] 系统内部记录的 `adoption_status` 为 `tentative` 或 `not_adopted`
- [ ] 数据库的作品正式设定表中没有新增这些数据

**测试**: `artifact_adoption_test.exs` — `"creative tool result produces tentative artifacts"` ✅

---

### 场景组 B：选择与偏好 (Selection)

#### B1 — 选择一个候选方案

**作为作者**，我对"方案2: 灵源重工"很满意，点击了选择按钮。
**系统应该**记录我的选择，并准备好进入采纳流程。

**验证点**：
- [ ] 我提交了 `choose_candidate` 动作
- [ ] 系统记录了我的选择偏好
- [ ] 此时作品设定仍未发生正式改变（仍处于 selection 阶段，非 adoption）

---

### 场景组 C：采纳边界 (Adoption Boundary)

#### C1 — 确认采用后正式写入

**作为作者**，我确认采用"灵源重工"作为本作品的反派。
**系统应该**正式执行采纳操作，将其写入作品设定。

**验证点**：
- [ ] 内部产生了一个 `AdoptionDecision`
- [ ] 数据库的作品设定表中现在出现了"灵源重工"
- [ ] Trace 记录了从"草稿生成"到"作者选择"再到"系统采纳"的完整过程

**测试**: `artifact_adoption_test.exs` — `"explicit adoption writes to production state"` ✅

---

#### C2 — 采纳冲突处理（过期失效）

**作为作者**，我尝试采用一个已经被我改乱了上下文的旧草稿。
**系统应该**检测到上下文已失效，并提示我"草稿已过期，请重新生成"。

**验证点**：
- [ ] 系统通过 `AdoptionBoundary` 拦截了过期的采纳请求
- [ ] 返回明确的错误或降级提示

---

### 场景组 D：诚实性 (Truthfulness)

#### D1 — 系统不谎报进度

**作为作者**，我看到 AI 的回复中说"我已经帮你写好了"。
**系统应该**确保这真的意味着它已经"采纳"了，而不是仅仅生成了草稿。

**验证点**：
- [ ] 如果 `adoption_status != :adopted`，TurnResult 严禁宣称"已写入作品"、"已保存设定"
- [ ] UI 上的状态显示必须与内部 `adoption_status` 严格一致

**测试**: `artifact_adoption_test.exs` — `"TurnResult honors adoption status"` ✅

## 4. 缺口

| 缺口 | 影响 | 建议处理 |
|------|------|---------|
| GAP-01 — 采纳过期校验 | 如果作者在多轮对话后才去点之前的"采用"按钮，内容可能已不合时宜 | 在 `AdoptionDecision` 中增加 `context_version` 或 `turn_id` 校验 |
| GAP-02 — 采纳冲突检测 | 两个类似的草稿同时点"采用"可能导致设定逻辑冲突 | 增加领域层的 Invariant 检查（如：作品只能有一个反派组织设定） |
