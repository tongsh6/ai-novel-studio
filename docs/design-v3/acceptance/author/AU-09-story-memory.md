> 作者视角：我的小说有大量设定——角色关系、伏笔线索、世界观规则。我需要一个地方能浏览、整理这些设定。最重要的是，当我和 AI 对话时，这些设定应该被自动引用。

### 场景组 C：设定生命周期

#### S6 — 从草稿到确认到废弃

**作为作者**，一条 AI 生成的设定最初是"草稿"。我审核后点"确认"→ 状态变为"已确认"，AI 在对话中会引用它。后来剧情改了这条设定不适用了，我点"废弃"→ AI 不再引用。如果改主意了，还可以"归档"保存记录。

**合法的状态变化**（系统内部保证）：
```
草稿 → 已确认 → 稳定
              → 废弃 → 归档
              → 冲突
```

**验证点**：
- [ ] "草稿"状态 → `confirmMemory` → "已确认"
- [ ] "已确认" → `deprecateMemory` → "废弃"
- [ ] "废弃" → `archiveMemory` → "归档"
- [ ] **非法跳转（如"归档 → 草稿"）→ 后端应拒绝。当前实现：后端 API 未校验非法转换** ❌

**代码**：`MemoryDetailDrawer.tsx` + `memoryApi.ts` ✅（前端操作）、❌（后端无 guard）

---

#### S7 — 锁定核心设定不被 AI 改动

**作为作者**，我有一条核心设定"灵气被垄断为能源"，这是整个世界观的基础。我把它锁定了。AI 在对话中仍然可以引用它（"因为灵气被垄断..."），但不能自动修改它的内容。

**验证点**：
- [ ] 锁定后 `locked = true`
- [ ] 锁定不阻止召回——AI 仍然可以引用
- [ ] 锁定后修改内容 → **当前实现：`update_changeset` 仍允许修改 content，未做锁定保护** ❌

---

#### S8 — 只在一定章节内有效的设定

**作为作者**，我设置了一条设定"主角的灵力在第一章被封印，第二章解开"。我可以标记这条设定只在第一章有效。当故事推进到第二章后，AI 应该不再引用这条设定（或标注为"已过期"）。

**验证点**：
- [ ] `valid_from` 和 `valid_until` 可设置叙事位置
- [ ] 当前叙事位置在窗口外 → 不召回或降权
- [ ] **当前实现：字段已定义但召回逻辑未使用** ❌

---

### 场景组 D：AI 对话中的记忆引用

#### S9 — 确认过的伏笔被 AI 自动使用

**作为作者**，我确认了一条伏笔"林瑶失踪与灵源矿区有关"。几分钟后我问 AI "林烬为什么要去矿区"，AI 的回答里自动引用了这条伏笔。我没有手动告诉 AI 这条设定——它是从记忆库里自动召回的。

**完整过程**：
```
1. 我确认伏笔 → MemoryItem(status=CONFIRMED, type=FORESHADOWING)
2. 我问问题 → 系统自动召回相关记忆 → 填到 AI 的 prompt 里
3. AI 回答里引用了这条伏笔
```

**验证点**：
- [ ] 记忆确认后进入记忆库
- [ ] 下一轮对话时 `recallMemories` 被调用
- [ ] 召回结果进入 `memory_summary` → prompt
- [ ] AI 回应体现记忆内容
- [ ] **当前实现：Step 2-3 未连通——`memory_summary` 写死为 nil** ❌

## 6. 缺口

| 缺口 | 具体表现 | 影响 |
|------|---------|------|
| GAP-01 — memory_summary 未接入 | `workspace_context.ex:27` 返回 nil | AI 对话时无法引用记忆库 |
| GAP-02 — 状态转换无后端 guard | API 层不校验合法转换路径 | 前端 bug 可导致归档→草稿回退 |
| GAP-03 — locked 字段未保护 | `update_changeset` 允许修改 locked 记忆的 content | 锁定形同虚设 |
| GAP-04 — 有效期窗口未生效 | `valid_from/valid_until` 定义但召回不用 | 章节限定的设定在全书中被引用 |
| GAP-05 — 召回端到端未验证 | 记忆 → recall → prompt → AI 回复链路未测试 | 不知道记忆是否真的进入了 AI 的上下文 |
| GAP-06 — 记忆生命周期无自动化测试 | 全靠手动操作验证 | 重构无保障 |
