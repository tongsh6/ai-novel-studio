# SU-02 切换作品

> 系统用户视角：我有多个小说项目（作品），可以在它们之间切换，每个作品有独立的对话上下文、设定和产出。切换作品就像切换项目文件——不会丢、不会串。

---

## 1. 我能做什么

| 我能做什么 | 系统怎么回应 |
|-----------|------------|
| 看当前在哪个作品里 | 界面顶部显示当前作品名 |
| 切换到另一个作品 | 对话区切换到新作品的上下文，之前的消息不丢 |
| 创建新作品 | 给新作品起名，系统初始化空的工作区 |
| 重新打开软件时回到上次的作品 | 自动恢复上次打开的 workspace |

---

## 2. 验收场景

### 场景组 A：查看和识别

#### A1 — 当前作品名始终可见

**作为系统用户**，我在顶部栏一眼就能看到当前在哪个作品里，不会搞混。

```
顶部栏: "《末世剑修》/ 第一卷"
```

**验证点**：
- [ ] 顶部栏显示当前作品名
- [ ] 未创建作品时显示占位提示（如"未命名作品"或"创建新作品"）
- [ ] 作品名和卷名有明显层级区分

**当前代码**：`WorkspaceChat.tsx` 顶部栏显示 `context.workTitle`，当前写死为 `"未定作品"`。✅

---

### 场景组 B：切换作品

#### B1 — 切换作品列表

**作为系统用户**，我点击顶部栏的作品名区域，弹出作品列表，选择另一个作品。

```
顶部栏点击区域:  [《末世剑修》 ▼]
                 ├─ 《末世剑修》        ← 当前
                 ├─ 《星际商战》
                 └─ 《古代悬疑》
```

**验证点**：
- [ ] 展示所有已创建的作品
- [ ] 当前作品有选中标记
- [ ] 切换后顶部标题立即更新
- [ ] 切换后对话区加载新作品的上下文（TOC、角色、统计等）
- [ ] 切回原作品时，之前的对话和状态完整恢复

---

#### B2 — 切换作品时重新加入 Channel

**作为系统用户**，切换作品后，WebSocket Channel 自动切换到新 workspace 的 topic。

```
当前: channel topic = "workspace:workspace-1"
切换到 workspace-2 后: channel topic = "workspace:workspace-2"
```

**验证点**：
- [ ] Channel leave 旧 topic → join 新 topic
- [ ] 新 topic join 成功后消息列表刷新为新作品的历史
- [ ] join 失败时有明确提示（如 "无法加载该作品"）
- [ ] 切换过程中不出现短暂连接断开

---

#### B3 — 切换时正在进行的 LLM 请求被取消或隔离

**作为系统用户**，我在作品 A 发了一条消息，AI 还在思考中，我切换到作品 B。作品 A 的请求要么被取消，要么结果只归入作品 A（不会串到 B）。

**验证点**：
- [ ] 切换作品后，旧作品的 pending 请求结果不会出现在新作品的消息列表
- [ ] 切回旧作品时，pending 请求的结果（如果已完成）出现在消息列表末尾

---

### 场景组 C：创建新作品

#### C1 — 创建新作品

**作为系统用户**，我在作品列表中点击"创建新作品"，输入作品名，系统为我初始化一个空的工作区。

```
作品列表:
  [《末世剑修》]
  [《星际商战》]
  ───────────────
  [+ 创建新作品]  →  弹窗: "作品名称: [____________]  [创建]"
```

**验证点**：
- [ ] 输入作品名后创建成功，自动切换到新作品
- [ ] 新作品显示欢迎消息（类似首次进入工作台）
- [ ] 不输入名称时"创建"按钮不可用
- [ ] 作品名有合理长度限制（如 1-50 字符）

---

#### C2 — 作品列表持久化

**作为系统用户**，我创建了 3 个作品后关闭软件，重新打开时作品列表仍然存在。

**验证点**：
- [ ] 作品列表本地持久化（Tauri app data 目录）
- [ ] 重启后自动恢复到上次使用的作品
- [ ] 作品对应的对话历史、设定、角色不丢失

---

#### C3 — 未命名作品

**作为系统用户**，我快速开始了一个新作品但还没想好名字，直接开始和 AI 聊，过程中产生了一些设定和对话。作品列表里它应该显示为一个可辨识的占位名，而不是空白或报错。

```
作品列表:
  [《末世剑修》]
  [未命名作品 · 2026-05-08 14:30]      ← 还没起名但已有内容
  [《古代悬疑》]
  ───────────────
  [+ 创建新作品]
```

**验证点**：
- [ ] 创建作品时名称可以为空，不阻塞创建流程
- [ ] 未命名作品在列表中显示占位名（如"未命名作品"），并附带区分信息（如创建时间、首条消息摘要）
- [ ] 多个未命名作品之间可区分（不能全是同一个"未命名作品"）
- [ ] 未命名作品内部的对话、设定、数据正常保存
- [ ] 后续可以给未命名作品改名

**改名**：
```
右键菜单:  [《末世剑修》]
           [未命名作品 · 05-08]  →  [重命名]  [删除]
           [《古代悬疑》]              ↓
                                 输入框: "末世剑修" [确认]
```

**验证点**：
- [ ] 改名后作品列表和顶部栏同步更新
- [ ] 改名不丢失已有数据
- [ ] 新名称校验同 C1（长度限制、非纯空格）

---

### 场景组 D：恢复状态

#### D1 — 上次使用的作品自动恢复

**作为系统用户**，我昨天在《末世剑修》的第三卷里写到一半，今天打开软件，自动回到这个位置。

**验证点**：
- [ ] 自动 join `workspace:<上次workspace_id>`
- [ ] 顶部显示《末世剑修》/ 第三卷
- [ ] TOC、角色等上下文重新加载

---

#### D2 — 上次的作品被删除或不可用时

**作为系统用户**，如果上次的作品因为某些原因无法加载（文件被删除、数据损坏），系统不会 crash，而是退回到作品选择列表。

**验证点**：
- [ ] 显示提示"上次的作品无法加载，请选择其他作品"
- [ ] 不出现白屏或无限 loading

## 4. 缺口

| 缺口 | 影响 | 建议处理 |
|------|------|---------|
| GAP-01 — 作品列表数据源 | 当前 `workId` 写死为 `"mock_work_123"` | 需后端提供 `GET /api/works` 或通过 Channel 消息获取列表 |
| GAP-02 — Channel 动态切换 | 当前 join 只执行一次，无 rejoin 机制 | `useEffect` 需依赖 `workspaceId`，变化时 leave 旧 channel + join 新 channel |
| GAP-03 — 作品元数据存储 | 作品名、创建时间等信息无存储 | 需 persistence 层支持 workspace CRUD |
| GAP-04 — 消息列表隔离 | 切换作品后消息列表需刷新 | 切换时 reset `messages` state，按 workspace 缓存或从服务端加载 |
| GAP-05 — 跨作品 pending 请求隔离 | 切换时旧作品的 LLM 请求可能返回 | Channel leave 后 push 会 reject，天然隔离；需确认 |
