# 原型验证二阶段决策记录

## 文档目的

本文档用于把原型验证二阶段已经确认的关键决策固化为后续设计与实现的约束基线。

它不是完整系统设计文档，而是：

- 记录已经确认的方向性判断
- 说明这些判断要解决什么问题
- 约束后续最小内核设计和原型实现

## 决策背景

一阶段原型已经证明：

- 本地 Web + API 工作台是可运行的
- 多项目、设定维护、章节推进、自动生成与审核流程可以形成基础闭环

但一阶段的默认前提仍然是：

- 用户已有较完整的格式化输入
- 系统主要承接“设定之后”的工作

这一点与真实创作起点不一致。真实用户往往先有的是：

- 模糊灵感
- 一些感觉
- 若干卖点
- 参考作品
- 尚未稳定的世界、角色和方向

因此二阶段的验证重心必须前移到“小说原点”。

## 已确认决策

### 决策 1：二阶段先验证内核，再验证最小工作流

#### 决策

二阶段不先做更完整的前端产品，而是优先验证系统底层机制是否成立，再用一条最小可运行工作流证明它能支撑真实创作。

#### 解决的问题

避免在内核未定义清楚时继续堆页面和交互，导致系统继续停留在“写作工作台增强版”。

#### 直接影响

后续设计优先级应是：

1. 小说空间模型
2. 候选变更模型
3. 分层记忆模型
4. 拆书资产模型
5. 结构特性升级模型

### 决策 2：构思阶段采用自由对话式共创

#### 决策

构思阶段的主交互形态采用自由对话，而不是固定流程向导或问卷式收集。

AI 的角色以“共创者”为主，以“拆解教练”为辅。

#### 解决的问题

解决用户在创作初期无法直接提供结构化信息的问题，使系统能够从模糊想法和感觉开始推进。

#### 直接影响

后续原型不应把前台主流程设计成强步骤表单。结构化沉淀应主要由系统在后台完成。

### 决策 3：讨论结果以结构化对象为第一落点

#### 决策

一次构思讨论是否成功，主要判断标准不是是否形成一篇完整说明文，而是是否形成了系统可持有的结构化对象。

文档可以存在，但属于表达层，不是事实源。

#### 解决的问题

避免系统继续以大段 prose 作为核心数据载体，导致后续记忆、比较、追因、候选变更和版本管理难以成立。

#### 直接影响

后续设计必须明确：

- 对象
- 关系
- 候选状态
- 正式状态
- 作用域
- 版本引用

### 决策 4：结构化优先级为 A > B > C > D

#### 决策

二阶段先结构化的对象优先级已经确认如下：

1. 小说元信息
2. 世界与设定
3. 角色与关系
4. 故事推进

#### 解决的问题

避免系统再次一上来就急于生成卷纲和章节，而忽略小说 identity、运行规则和角色关系这些更上层约束。

#### 直接影响

后续最小工作流应从“小说是什么”开始，而不是从“第 1 章怎么写”开始。

### 决策 5：每本小说都要有独立的“小说空间”

#### 决策

每本小说不是单纯的一条项目记录，而是一个持续存在的“空间”。

这个空间既是数据容器，也是运行上下文。

#### 解决的问题

解决当前项目模型过于扁平，无法承载长期演化、候选区、分层记忆、参考资产和运行态的问题。

#### 直接影响

小说空间至少应承载：

- 正式对象
- 候选对象
- 参考资产
- 讨论上下文
- 记忆
- 版本
- 启用能力
- 当前运行状态

### 决策 6：记忆采用分层且可调优先级机制

#### 决策

记忆不是固定排序的单层库，而应按系统、作者、小说、卷、章节等层级存在，并允许在不同作用域内手动调整优先级。

#### 解决的问题

避免 agent 只能被动读最近上下文，无法在不同小说、不同卷章阶段使用不同记忆策略。

#### 直接影响

记忆系统后续不能只做“补全文本上下文”，还要支持：

- 历史版本找回
- 差异比较
- 决策追因
- 旧信息再吸收

### 决策 7：讨论结果默认进入候选区

#### 决策

AI 讨论形成的设定调整、方向调整、prompt 调整等结果，默认不直接进入正式系统，而是先成为候选变更。

#### 解决的问题

避免 AI 共创过程中出现“聊天即生效”，从而破坏正式设定边界。

#### 直接影响

后续系统必须区分：

- 正式版本
- 候选变更

且候选区必须支持轻提示可见，而不是强制立即处理。

### 决策 8：候选变更支持整批确认、对象确认与作用域发布

#### 决策

候选变更的确认粒度不能只有一种，必须同时支持：

- 整批确认
- 对象级确认

确认后的生效范围也必须可选，例如：

- 仅未来生效
- 从某一卷起生效
- 从某一章起生效
- 全局重定义

#### 解决的问题

避免系统只能做简单的“通过 / 放弃”，无法处理创作中常见的局部吸收和范围限定。

#### 直接影响

后续候选模型需要显式承载：

- 来源讨论
- 对象集合
- 确认状态
- 发布作用域
- 与历史内容的潜在冲突

### 决策 9：高风险动作不得自动生效

#### 决策

凡是会：

- 改变正式设定
- 影响后续写作方向
- 改变系统行为或写作策略

的动作，都视为高风险动作，只能停在候选态。

#### 解决的问题

确保成熟后的小说 agent 即使具备半自动推进能力，也不会越过用户的正式决策权。

#### 直接影响

后续 agent 的自动化边界必须采用“低风险直做，高风险候选化”的模式。

### 决策 10：参考作品首先是结构样本，其次才是模板

#### 决策

参考作品主要用于拆解其结构方法，而不是直接作为风格模板复刻。

重点应拆出：

- 题材与定位方式
- 卖点结构
- 世界规则组织方式
- 角色功能结构
- 冲突升级方式
- 节奏组织方式
- 风格形成方式

#### 解决的问题

避免系统把“参考作品输入”退化为“生成一本像它的小说”。

#### 直接影响

后续拆书设计应优先输出：

- 结构结论
- 可复用对象

### 决策 11：拆书支持独立模式与开书辅助模式

#### 决策

拆书不是单一路径，必须支持两种入口：

- 独立拆书
- 开书辅助拆书

归属规则已经确认：

- 独立拆书默认落作者资产层
- 开书辅助拆书默认先落当前小说层，确认后再升级

#### 解决的问题

解决“拆书到底是长期资产，还是当前项目工具”这一归属冲突。

#### 直接影响

后续资产模型必须区分：

- 作者级资产
- 小说级资产
- 升级路径

### 决策 12：多参考作品的组织方式和流程顺序都可配置

#### 决策

开新书时允许选择拆解 `N` 本参考作品，`N` 需要有上限。

这些参考作品之间既可以是：

- 平行参考
- 主次参考

参考作品进入构思后的处理顺序也不可写死，作者可自行选择：

- 先分析
- 先出方向
- 先分析后出方向
- 先出方向后反查依据

#### 解决的问题

避免把“参考作品辅助构思”硬编码成一种单线流程。

#### 直接影响

后续原型应体现“流程可编排”能力，而不是固定向导。

### 决策 13：元数据结构本身可进化

#### 决策

小说元数据结构不是一次定义终局。AI 在讨论中发现结构缺口时，应实时提示结构变化候选，默认只影响当前小说。

这些变化形成“待提升特性清单”，由用户决定是否上升。

#### 解决的问题

解决固定 schema 难以覆盖不同题材、不同风格小说的问题。

#### 直接影响

后续设计必须支持：

- 当前小说局部试出的结构特性
- 作者级能力提升
- 平台级能力沉淀

### 决策 14：结构特性的上升路径分为小说级、作者级、平台级

#### 决策

结构特性采用逐层上升机制：

1. 先在当前小说内试出
2. 用户确认后进入作者级能力库
3. 更成熟后再进入平台级能力层

进入更高层后的能力不默认强启，而由 AI 按上下文建议启用。

#### 解决的问题

避免把某一本小说里试出来的局部结构过早全局化。

#### 直接影响

后续能力系统至少要区分：

- 小说级能力
- 作者级能力
- 平台级能力

### 决策 15：成熟后的小说 agent 采用分级自动化

#### 决策

当小说空间逐渐成熟后，agent 应具备半自动推进能力，但必须遵守明确权限边界。

- 低风险动作可自动执行
- 高风险动作只能形成候选

#### 解决的问题

既避免 agent 长期停留在被动工具状态，也避免其直接越权修改小说正式走向。

#### 直接影响

后续 agent 设计不能走“全自动写书”，而应走“带权限边界的半自动协作”。

## 当前不在本阶段直接解决的内容

本阶段暂不要求优先解决：

- 完整的生产级前端体验
- 全量作品拆书库
- 全功能检索系统
- 多用户平台级能力治理
- 最终稳定 schema 的一次性定稿

这些内容可以进入后续阶段，但不作为本轮原型验证的先决条件。

## 对后续工作的约束

后续的系统设计、数据建模和原型实现，不应违反以下约束：

- 不把主交互退回成问卷式表单
- 不把结构化对象退回成一段大文本
- 不让讨论结果默认直接变成正式设定
- 不让局部结构试验自动上升为全局能力
- 不让 agent 自动执行高风险动作
- 不把二阶段目标误解为“做更大的 UI”

## 下一步建议

在本决策记录基础上，下一步应进入“二阶段最小内核设计”，重点明确：

1. 小说空间模型
2. 候选变更模型
3. 分层记忆模型
4. 拆书资产模型
5. 结构特性升级模型

这些模型一旦明确，才适合进入下一轮原型实现。
