## 设计边界

### 这层负责什么

- 把 V1 动作编排成最小可运行链路
- 组织跨表写入
- 推进最小阶段状态
- 写入 `decision_logs`
- 返回工作台快照或阅读投影

### 这层不负责什么

- HTTP 路由
- WebSocket / 流式输出
- 前端状态管理
- 真正的 LLM 调用
- 派生分析打分
- 连续性冲突检查

---

## 当前实现取舍

### 1. 先用本地 stub 生成

本阶段不接模型，章节细纲和正文草稿都由本地规则模板生成。  
原因是当前重点是验证：

- 动作是否可编排
- 对象是否可持久化
- 阅读态是否可闭环

### 2. 关键动作自动写决策日志

当前动作会自动写入：

- 创建立项底稿
- 生成章节细纲
- 生成正文草稿
- 修订正文草稿

这样至少保证最小闭环下的关键变更不会丢。

当动作是“按要求重生成”时，决策日志还会显式记录：

- 修改要求文本
- 执行模式
- 关联章节 / 草稿版本

这样后续回看最近决策时，不需要再从正文或章节摘要里反推“这一版为什么改”。

### 3. 阅读态先做运行时投影

`enter_read_mode` 当前直接把章节与最新草稿投影成阅读数据。  
这不是缓存表，也不是源对象。
