# AGENTS.md

## 角色

你正在协助实现一个“对话式小说工作台”原型。  
这不是通用聊天应用，也不是创作 ERP。

## 产品定位

一个以对话为主入口、以结构化内核为隐性支撑、以阅读模式为结果闭环的小说创作工作台。

## 当前优先级

先验证最小闭环：

灵感输入 -> 作品立项 -> 章节细纲 -> 正文草稿 -> 阅读模式

不要过早扩展到：
- 多人协作
- 权限系统
- 自动发布
- 花哨图谱
- 创作 ERP 后台

## 必读文件顺序

1. `00-vision.md`
2. `01-domain-model-full.md`
3. `02-v1-scope.md`
4. `03-sqlite-minimal-schema.md`
5. `05-decisions.md`

## 当前实现建议

### 数据层
V1 优先 SQLite。  
核心原则：
- 主键 `TEXT`
- JSON 统一字符串存储
- 时间统一 Unix 毫秒
- 扩展字段统一走 `extensions_json`
- 备注走 `notes_json`

### 最小表范围
优先：
- works
- characters
- outlines
- volumes
- chapters
- drafts
- decision_logs
- continuity_states

### 对象边界
不要把“领域词典”直接等同于数据库字段表。  
要区分：
- 对象
- 核心字段
- 扩展字段
- 文档资产
- 连续性状态
- 派生投影

## 编码时的硬约束

### 1. 不要为了看起来完整而过度实现
先跑通最小闭环。

### 2. 不要把分析指标写回源对象
可读性、节奏分、崩盘风险等属于派生分析。

### 3. 不要把备注和核心事实混在一起
用户确认事实、AI 提议、自由备注要区分。

### 4. 决策日志不能省
关键变更必须留痕。

### 5. 连续性状态不能省
否则长篇抗崩能力不足。

## UI 形态约束

优先：
- 单工作台
- 对话流主导
- 结构侧栏辅助
- 正文工作态
- 阅读态

避免：
- 多页面后台
- 大量表单
- 功能菜单堆满
- 先做可视化大屏

## 工作方式

当你开始实现时：

1. 先确认当前任务是否服务于最小闭环。
2. 优先使用最小对象集。
3. 若想新增字段或表，先检查：
   - 是否真的影响主链路
   - 是否只是扩展字段即可
   - 是否应该先记入未来项而不是当前实现
4. 所有裁剪与新增都应同步到 `05-decisions.md` 或新增相应实现文档。
