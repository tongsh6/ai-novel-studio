# Novel Output Milestones / 小说产出阶段目标

> 最后更新：2026-05-24
>
> 角色：本文是 AI Novel Studio 的长期产出能力目标。它不替代 `docs/product/user-journeys.md`、`docs/design-v3/acceptance/` 或 `tasks/NEXT.md`，而是回答：
>
> - 产品最终要支撑多大规模的小说生产？
> - “产出 10 万 / 50 万 / 100 万 / 500 万字”应该怎样验收？
> - 哪些能力缺口必须先补，不能只用脚本堆字数冒充产品完成？

---

## 1. 基本原则

这些目标不是“让模型一次吐出 N 万字”，而是验证 AI Novel Studio 是否具备稳定支撑不同规模长篇小说生产的产品能力。

字数只是外显指标。真正要验收的是：

- 作品规划能力
- 章节连续产出能力
- 作品事实与 canon 治理
- 长期记忆和上下文压缩
- 伏笔、人物、世界观、时间线一致性
- 章节采纳、修订、阅读投影和导出
- 中断恢复、失败重跑、质量检查和可审计 trace

任何阶段都禁止用重复段落、模板废话、无意义内心独白、系统提示或工具日志凑字数。

---

## 2. 统计口径

| 项 | 口径 |
|---|---|
| 正文有效字数 | 只统计小说正文，不统计大纲、设定、作者笔记、prompt、系统说明、工具日志。 |
| 标题/卷名 | 可单独统计，但不计入正文硬指标。 |
| 标点和空白 | 默认不计入有效字数。 |
| 章节下限 | 每章正文有效字数必须达到阶段下限，不能用平均值掩盖短章。 |
| 重复内容 | 重复段落、模板化套话和明显注水不计入有效字数。 |
| 章节完整性 | 每章必须有标题、序号、所属卷/篇章和正文。 |
| 系统泄漏 | 出现 prompt、工具日志、“作为 AI”等出戏文本，该章不通过。 |

字数统计必须由确定性脚本或产品统计模块完成，不能使用 LLM 自报。

---

## 3. 阶段目标

| 阶段 | 名称 | 总正文有效字数 | 单章正文有效字数 | 预计章数 | 产品含义 |
|---|---|---:|---:|---:|---|
| P1 | 10 万字最小长篇闭环 | ≥100,000 | ≥1,000 | 约 100 章 | 验证从作品设定、章节规划、逐章产出、采纳、阅读到导出的最小长篇主链。 |
| P2 | 50 万字中长篇连载闭环 | ≥500,000 | ≥2,000 | 约 250 章 | 验证中长篇连载能力，重点是记忆、伏笔、人物状态和断点续写。 |
| P3 | 100 万字成熟长篇生产闭环 | ≥1,000,000 | 3,000-5,000 | 约 200-333 章 | 验证多卷结构、主支线协同、长期 canon 和质量治理。 |
| P4 | 500 万字工业化超长篇生产闭环 | ≥5,000,000 | 5,000-8,000 | 约 625-1,000 章 | 验证工业化长篇生产系统，包括批量任务、失败恢复、跨卷一致性和大规模质量检查。 |

---

## 4. 通用验收标准

### 4.1 数量标准

| 指标 | 标准 |
|---|---|
| 总正文有效字数 | 达到对应阶段目标。 |
| 单章正文有效字数 | 每章都达到对应阶段下限。 |
| 缺章率 | 0。 |
| 空章/重复章 | 0。 |
| 导出完整性 | 可导出 Markdown / txt / epub 至少一种，章节顺序完整。 |

### 4.2 结构标准

每部验收作品至少应具备：

- 作品标题
- 类型/题材
- 核心卖点
- 目标读者
- 叙事基调
- 主角设定
- 世界观基础
- 主线目标
- 分卷或篇章计划
- 章节大纲
- 已确认 canon
- 伏笔清单
- 人物状态表

P1 可允许简化，但 P2 以后必须完整。

### 4.3 章节质量标准

每章至少满足：

- 有明确场景或事件。
- 有剧情推进、人物变化、信息增量或冲突升级中的至少一项。
- 不只是前情总结或设定复述。
- 不出现明显前后矛盾。
- 不出现系统 prompt、工具日志、内部状态或“作为 AI”等出戏文本。
- 不用重复段落、模板句式或低信息密度描写凑字数。

### 4.4 连续性标准

每 10-20 章至少做一次连续性检查：

- 人物姓名、身份、关系稳定。
- 主角目标和阶段目标可解释。
- 已确认设定不被静默改写。
- 重要死亡、受伤、地点变化、阵营变化保持一致。
- 时间线顺序可解释。
- 伏笔状态可追踪：未埋、已埋、推进中、已回收、废弃。
- 世界规则、战力、资源、地理边界不无故漂移。

### 4.5 产品链路标准

验收不能只检查生成出来的文件。每个阶段都必须至少覆盖一条真实产品链路：

```text
创建作品
→ 生成/采纳设定
→ 生成章节计划
→ 逐章生成正文
→ 采纳或修订
→ 更新 canon / memory / projection
→ 阅读模式查看
→ 导出完整小说
→ 重新打开后继续创作
```

外部自动化必须从真实工作台入口驱动，不得在生产 UI 中加入验收专用 hook。

## 5. 阶段 Definition of Done

### P1 Done：10 万字最小长篇闭环

- 正文有效字数 ≥100,000。
- 每章正文有效字数 ≥1,000。
- 章节数约 100 章，或以有效字数达标且结构完整为准。
- 可从真实工作台创建作品、生成章节、采纳正文、阅读和导出。
- 有完整章节目录。
- 重启后能继续生成下一章。
- 抽样至少 10 章，无明显断裂、系统泄漏、空章或重复章。
- 至少一条外部 Tauri / Playwright 场景化验收证明真实产品链路成立。

### P2 Done：50 万字中长篇连载闭环

- 正文有效字数 ≥500,000。
- 每章正文有效字数 ≥2,000。
- 有分卷结构。
- 每 10 章有剧情摘要或阶段状态。
- 人物状态、伏笔、canon 可追踪。
- 随机抽样至少 25 章通过连续性检查。
- 能从最近章节继续写，不丢上下文。
- 导出后目录、章节顺序、正文完整。

### P3 Done：100 万字成熟长篇生产闭环

- 正文有效字数 ≥1,000,000。
- 每章正文有效字数 3,000-5,000；低于 3,000 不通过，高于 5,000 需标记为超长章。
- 至少 3 个大篇章或卷。
- 每卷有卷首目标和卷末总结。
- 主线、支线、人物成长线有阶段性推进。
- 关键设定变更必须经过采纳/确认，不能被 AI 静默改写。
- 自动检测重复桥段、设定漂移、时间线冲突。
- 抽样至少 50 章通过质量验收。
- 可生成全书设定索引和前情提要。

### P4 Done：500 万字工业化超长篇生产闭环

- 正文有效字数 ≥5,000,000。
- 每章正文有效字数 5,000-8,000。
- 章节数约 625-1,000。
- 支持长期批量任务、失败恢复、断点续跑。
- 支持跨卷 canon 查询和一致性检查。
- 支持章节级质量报告。
- 支持重复内容、注水和风格漂移检测。
- 支持全书导出、分卷导出、章节重写。
- 抽样至少 100 章通过人工或半自动质量验收。
- 关键人物、势力、地点、时间线、伏笔状态可完整追踪。

## 6. P1 反推能力缺口

P1 是当前最适合转成承重 slice 的阶段目标。P1 不要求工业化批量生产，但必须证明小说产出主链从真实工作台可执行。

| 缺口 | 需要补齐的产品能力 | 关联 Journey / AU |
|---|---|---|
| 章节计划 | 从作品设定生成可采纳章节目录或篇章计划。 | Journey D / AU-02 / AU-05 |
| 正文生成 | 按指定章节目标生成正文，不把设定或摘要当正文。 | Journey D / AU-05 |
| 正文采纳 | 章节正文默认 tentative，采纳后才成为作品事实。 | Journey F / AU-05 |
| 阅读投影 | 采纳后的章节可在 ReadingMode 看到，未采纳正文不可见。 | Journey G / AU-08 |
| 字数统计 | 确定性统计正文有效字数、章节字数、缺章和重复章。 | Journey D / G / J |
| 连续性治理 | 每章写作消费当前 canon、最近章节、已确认记忆和章节计划。 | Journey B / H / I |
| 导出 | 从正式作品事实导出完整小说。 | Journey G / J |
| 外部验收 | 外部自动化驱动真实工作台完成 P1 最小链路并输出 artifact。 | 工程验收 / vertical slice |

## 7. 建议推进顺序

AU-05 canon conflict recovery、P1 chapter plan minimum 与 P1 chapter draft generation 已闭环后，P1 能力建议拆为以下产品 checkpoint；当前队首为第三项：

1. **P1-chapter-plan-minimum**：真实工作台生成并采纳 10-20 章章节计划。（已闭环：`artifacts/slice-verify/p1-chapter-plan-minimum-tauri/summary.json`）
2. **P1-chapter-draft-generation**：按章节计划生成单章正文草稿，并证明未采纳正文不进入阅读投影。（已闭环：`artifacts/slice-verify/p1-chapter-draft-generation-tauri/summary.json`；正文有效字数达到下限仍待后续字数/扩写 checkpoint）
3. **P1-chapter-adoption-reading**：采纳章节正文后进入作品事实和阅读投影。（当前队首）
4. **P1-word-count-audit**：确定性统计章节正文有效字数、总字数、短章、空章、重复段落。（checkpoint A 已闭环：空章/短章判定 + P1 门槛 + ReadingMode 短章标记与达标进度，`artifacts/slice-verify/p1-word-count-audit-tauri/summary.json`；重复段落与缺章率归 checkpoint B/C）
5. **P1-export-minimum**：导出完整 Markdown/txt，目录和章节顺序可验证。
6. **P1-100k-dogfood-run**：真实工作台或产品任务链完成 10 万字狗粮产出，并输出验收报告。

这些 checkpoint 不能用旁路脚本替代真实产品链路。脚本可以作为外部 driver、统计器或验收器，但产品能力必须沉淀在工作台、后端主链、持久化事实和阅读/导出消费者中。

---

## 8. 验收产物

每次阶段验收至少输出：

- `artifacts/novel-output/<milestone-id>/summary.json`
- `artifacts/novel-output/<milestone-id>/word-count.json`
- `artifacts/novel-output/<milestone-id>/chapter-quality.md`
- `artifacts/novel-output/<milestone-id>/continuity-report.md`
- `artifacts/novel-output/<milestone-id>/export/`
- 对应的 Tauri / Playwright 场景化验收 summary

最终汇报必须区分：

- 外部自动化驱动真实页面的验收
- 后端/Channel/组件局部验证
- 字数与质量统计
- 尚未闭环的产品缺口
