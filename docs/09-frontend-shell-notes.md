# 09-frontend-shell-notes

## 目的

本文件记录当前单工作台前端壳的边界，防止 UI 很快滑向多页面后台或复杂管理台。

---

## 当前页面结构

只有一个页面：

- 左侧：作品列表 + 新建立项表单
- 右侧：当前作品工作台 / 阅读态切换

工作台态只包含：

- 对话入口
- 当前作品概览
- 章节列表
- 当前章细纲信息
- 最新草稿
- 最近决策

其中“最新草稿”当前会直接展示：

- 当前版本号
- 字数
- 是否为首稿或修订稿
- 如果是修订稿，则显示来源版本

其中“最近决策”当前会直接展示：

- 动作类型
- 时间
- 本轮修改要求
- 执行模式
- 草稿版本号（如有）

并且可以点击某条决策，直接把工作台定位回关联章节，并自动把决策卡片和当前章详情区滚进视口。

阅读态只包含：

- 阅读目录
- 当前章纯净正文
- 当前可阅读版本的来路说明

---

## 当前已串的接口

- `GET /api/health`
- `GET /api/works`
- `POST /api/works`
- `GET /api/works/{workId}/workbench`
- `POST /api/works/{workId}/chapters/{chapterId}/generate-outline`
- `POST /api/works/{workId}/chapters/{chapterId}/generate-draft`
- `POST /api/works/{workId}/chapters/{chapterId}/revise-draft`
- `GET /api/works/{workId}/reading`

---

## 当前对话入口形态

- 消息流当前只在浏览器本地维护
- 不新增后端对话表
- 不新增聊天接口
- 未立项时，对话入口可直接触发作品立项
- 立项支持前端本地多轮补槽位：
  - 标题
  - 题材
  - 一句话卖点
- 作品内修改请求支持前端本地澄清：
  - 先改细纲
  - 或直接重出草稿
- 通过最小意图识别映射到现有动作：
  - 立项
  - 生成细纲
  - 生成草稿
  - 修订草稿
  - 切到阅读态
  - 返回工作台
  - 查看当前章状态

这一步的目的不是实现真正的小说对话 Agent，而是先让“对话作为入口”在单工作台里成立。

当前限制：

- “再狠一点”“节奏快一点”这类指令现在会通过：
  - `instructionText`
  - `rewriteMode` / `reviseMode`
  传入现有后端 stub 生成器
- 当前仍然不是完整可控改写引擎，但修改要求已经能影响细纲和草稿输出
- 当前已有草稿时，前端会优先走独立的 `revise-draft` 动作，而不是继续混用首次生成语义

---

## UI 设计约束

- 单工作台优先
- 少按钮，少表单
- 当前章优先
- 阅读态必须独立于工作台态
- 不做多页面后台导航

---

## 当前刻意不做

- 对象侧栏抽屉
- 复杂筛选
- 多作品并行编辑
- 局部改写面板
- 图谱或分析大屏

这些都不是当前最小闭环的必要条件。
