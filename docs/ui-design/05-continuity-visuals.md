# 连续性状态 (ContinuityState) 视觉与数据规范

## 1. 设计初衷
小说创作的“长篇抗崩”能力依赖于对状态的精确感知。UI 的任务是让这些隐性数据通过“微标”和“悬浮”无感地进入作者视野。

## 2. 视觉符号系统 (The Iconography)
建议使用 16x16px 单色图标：
- **[HP] 物理态**：线性血条感。数据映射：`current_value_json.health_status`。
- **[POS] 位置态**：定位锚点感。数据映射：`current_value_json.coordinate`。
- **[BAG] 持有态**：方块堆叠感。数据映射：`current_value_json.item_list`。
- **[CORE] 核心意图**：靶心感。记录角色当前阶段的首要目的（如：复仇、逃亡）。

## 3. 分层呈现策略

### A. 微缩态 (Micro-Status)
- **位置**：左侧角色列表底部。
- **样式**：极细进度条（2px）+ 3个小图标。
- **逻辑**：仅显示“当前最显著”的三个状态。

### B. 行内感应态 (Inline Hover)
- **位置**：正文中的角色关键词。
- **样式**：鼠标悬浮时出现的半透明黑色气泡（Ghost Card）。
- **内容**：
    - [核心动机]：一句话描述（来自 `DecisionLog`）。
    - [关键变化]：最近3章内的状态变更（如：-失血，+获得密信）。

### C. 冲突态 (The Conflict Engine)
- **位置**：正文行间或侧边栏顶层。
- **样式**：红色波浪线下划线 + 侧边警告标志 `[!]`。
- **逻辑**：当 AI 审计发现“物理定律违背”或“人物动机断裂”时强行弹出。

## 4. 交互语义 (Interactivity)
- **点击状态图标**：溯源模式。将视图自动滚动到该状态产生的 `DecisionLog` 段落。
- **拖拽状态卡片**：将状态注入对话框。自动生成指令：“@AI，请基于 [林恩.重伤] 这个事实，重写这段对话。”
