# UI 重构总览：分层适配策略

## 1. 核心理念
基于“对话优先，结构兜底”的后端架构，UI 层不再是一个静态的表单集合，而是一个**根据创作阶段和用户熟练度动态演化的交互界面**。

## 2. 三层适配模型 (The Tri-Tier Model)

| 模式 | 目标用户 | 交互核心 | UI 隐喻 |
| :--- | :--- | :--- | :--- |
| **引导模式 (Beginner)** | 小白作者 | 陪伴式对话、自动化卡片 | 灵感孵化器 |
| **协作模式 (Expert)** | 经验作者 | 三栏对照、版本管理、决策锚点 | 叙事指挥部 |
| **禅定模式 (Master)** | 大神作者 | 极简阅读态、指令搜索、逻辑审计 | 架构师控制台 |

## 3. 技术映射
- **Router 映射**：引导模式倾向于自动填充缺失参数（Autofill），协作模式强调参数确认（Clarification）。
- **Executor 映射**：所有模式共享相同的后端执行器，但结果呈现不同（小白看卡片，大神看正文）。
- **DecisionLog 映射**：作为 UI 的“历史回溯”基础，支持在任何模式下查看“为什么这么写”。
- **ReadingProjection 映射**：所有模式的最终收束点，提供一致的成品审看体验。

## 4. 模式切换机制
- 用户可在顶栏或通过指令（如“切换到专家模式”）进行无缝切换。
- 系统根据作品当前 `stage`（立项/细纲/草稿）自动推荐最佳模式。
